## 1. โปรเจ็กต์คืออะไร

ระบบเฝ้าดูโรงเรือนวัวนมราคาถูกสำหรับเกษตรกรรายย่อย ไม่ต้องติดอะไรบนตัววัว:

- **กล่อง IoT** (ESP32-S3 + หัววัด SHT40) วัดอุณหภูมิ/ความชื้น → คำนวณ THI (ดัชนีความเครียดจากความร้อน)
- **กล้อง IP (Dahua)** ในวงแลนฟาร์ม กล่องดึงภาพนิ่งทุก 15 วิแล้วส่งขึ้น server ผ่านเน็ต 4G (ไม่ส่งวิดีโอ ไม่ต้องมีคอมที่ฟาร์ม)
- **AI (YOLO26m ONNX 480)** ตรวจท่าวัว + ติดตาม**วัวเป้าหมาย 1 ตัว** → เวลานอน / ยืน / กิน + การเดิน เทียบกับ THI
- **เปเปอร์:** อาจารย์จะส่งงานประชุมวิชาการนานาชาติ**ก่อนสิ้นปี 2569** · **เน้นฮาร์ดแวร์** (ความเสถียร, ข้อมูลครบ, ความแม่นเซ็นเซอร์เทียบเครื่องอ้างอิง, แบนด์วิดท์, ไฟ, ราคา BOM) ส่วน AI ติดตามวัวเป็นตัวอย่างการใช้งาน

## 2. การตัดสินใจที่ล็อกแล้ว (อย่าเปิดประเด็นใหม่ ถ้าผู้ใช้ไม่ได้ขอ)

- **เน้นฮาร์ดแวร์** ในเปเปอร์ (อาจารย์: "ก็คงต้องเน้น hardware แล้วล่ะครับ มาขนาดนี้")
- **ไปฟาร์ม 6 และ 7 ธ.ค. 2569 เท่านั้น** (6 = ติดตั้ง + วันทดสอบ, 7 = วันเก็บจริง) ไม่มีการไปสำรวจก่อน ไม่มีเก็บระยะยาว
- **ใช้ภาพนิ่ง ไม่ใช้วิดีโอ** · เก็บที่รอบ **15 วิ** แล้วตอนวิเคราะห์ค่อยลดเป็น 30/60/120/300 วิ เทียบกับวิดีโออ้างอิง เพื่อเลือกรอบที่เหมาะ (Mitlöhner 2001: 1–15 นาทีพอสำหรับสัดส่วนเวลา · Ledgerwood 2010: นับจำนวนครั้งต้อง ≤ 30 วิ)
- **คงโมเดล YOLO26m** (ไม่เปลี่ยนเป็น YOLOv8) · ภาพย่อแบบยืด (stretch) 480
- **ท่า: นอน / ยืน / กิน** · ดื่มน้ำ = ยืน · **นอนกิน = นอน** (จดแยกไว้ในวิดีโออ้างอิง)
- **ไม่พ่นสี/ติดเครื่องหมายบนตัววัว** → ติดตามด้วยตำแหน่งอย่างเดียว (position-v2 + ทำนายการเดิน) · ข้อจำกัด: วัวเป้าหมายนอนลงตรงที่วัวข้าง ๆ ยืน อาจสลับตัว → วัดจริงแล้วรายงานตรง ๆ
- **ไม่มีสัตวแพทย์ตอนนี้** · เป้าหมาย = **จบโปรเจ็กต์ + ระบบนิ่ง**
- **การแบ่งภาพฟาร์มเป็นชุดฝึก/ชุดทดสอบ ยังไม่ตัดสินใจ** ผู้ใช้จะบอกเองตอนใกล้ทำ dataset (ภาพทุกภาพของ 2 วันเก็บครบ)
- **LINE เลื่อนไปทำตอน hackathon** (ห้ามเสนองาน LINE ถ้าไม่ได้ถูกถาม · ถ้าจะทำ ต้องแก้ broadcast ไปทุกคนก่อน)
- **ห้ามอ้างในเปเปอร์ว่า LSTM / Gemini / LINE ใช้งานจริง**
- **เซ็นเซอร์:** XY-MD02 (SHT20, RS485) เสียแล้ว → เปลี่ยนเป็น **SHT40 I2C** (เช็กของแท้แล้ว: chip ตอบเป็น sht4x)

## 3. สถานะตอนนี้ (26 พ.ย. 2569)

- เลือกวัวเป้าหมายที่รอบ 15 วิได้ · เน็ตหลุดไม่ทำให้การติดตามจบ (ช่องว่างถึง 300 วิ)
- สถานะกล่อง/กล้องตามรอบจริง · แยก "กล่องเงียบ" กับ "กล่องออนไลน์แต่เซ็นเซอร์ไม่ส่ง" · การ์ด THI บอกว่าค่าเก่าถ้าเกิน 10 นาที
- ตารางหลักฐานฮาร์ดแวร์ `tb_device_heartbeats`, `tb_camera_frames`, คอลัมน์ `tb_sensor_readings.received_at`
- เครื่องมือเทียบผล: `compare_video.js` (เทียบกับวิดีโอ ตามรอบถ่าย), `compare_sensor.js` (เทียบกับเครื่องอ้างอิง)

### Performance (ตรวจ 27 พ.ย.)
- **หน้าเว็บ (ทำแล้ว):** กราฟ ApexCharts โหลดเฉพาะหน้าที่มีกราฟ (ไฟล์ที่ต้องโหลดก่อนเปิดหน้า 803 → 261 KB gzip), ภาพพื้นหลัง login 6.3 MB → 174 KB, farm_detail ไม่ดึง multimodal-status/cameras ซ้ำ, ดึงข้อมูลทุก 15 วิ (เท่ารอบเซ็นเซอร์) และหยุดตอนแท็บซ่อน
- **firmware 1.6.2:** ค่าเซ็นเซอร์ไม่รอตอนกล้องส่งภาพ (ดูหัวข้อฮาร์ดแวร์)
- **ฐานข้อมูล (branch `perf/db-queries`):** ค่าเซ็นเซอร์ของฟาร์มอ่านด้วย `sr.id_farms = $1` อย่างเดียว (ใช้ index `(id_farms, recorded_at)`) แทน `d.id_farms = $1 OR sr.id_farms = $1` ที่อ่านทั้งตาราง · ค่าล่าสุด/แรกสุดใช้ `ORDER BY … LIMIT 1` แทน MAX/MIN · ผูกกล่องกับฟาร์มแล้ว `claimUnassignedReadings` เติม `id_farms` ให้ค่าที่ส่งมาตอนยังไม่ผูก · **กติกา: ค่าเซ็นเซอร์เป็นของฟาร์มที่กล่องผูกอยู่ตอนวัด** (ย้ายกล่องไปฟาร์มอื่น ค่าเก่าอยู่ฟาร์มเดิม) · migration `20261127_query_indexes_and_drop_unused.sql` เพิ่ม index และลบ 6 ตารางที่ไม่มีโค้ดใช้ (tb_alerts, tb_ai_advices, tb_thi_forecasts, tb_behavior_logs, behavior_logs, tb_farmer_daily_actions)
- **ยังไม่ทำ:** pool `statement_timeout` (Supabase pooler พอร์ต 6543 แบบ transaction อาจไม่รับ startup parameter ต้องทดสอบก่อน) · firmware เปิด HTTPS ใหม่ทุกครั้งที่ส่ง และจอใช้ SPI แบบซอฟต์แวร์ (เสี่ยง ไม่ทำก่อนไปฟาร์ม) · เวลา YOLO บน Render ยังไม่เคยวัด (บน M2 1 thread = 0.44 วิ/ภาพ) → วัดตอนซ้อมกล้อง ถ้าไม่ทันค่อยลอง INT8 · ฟอนต์ยังเป็น .ttf (Cloudflare บีบอัดให้แล้ว)

### ฮาร์ดแวร์ — ระยะ 2 กำลังทำ
- **firmware 1.6.0 แฟลชลงบอร์ดแล้ว และ merge เข้า main แล้ว** ทำงานจริงบนโต๊ะ (ผลรายงาน 24 ชม. วันที่ 27 พ.ย.: ออนไลน์ 100%, heartbeat 288/288, ไม่รีบูต, ค่าถึง server มัธยฐาน 1.8 วิ):
  - **พบว่า 1.6.0 ส่งค่ารอบละ ~16 วิ (อ่านทุก 2 วิ แล้วเช็ก ≥ 15 วิ) → ครบ 93.8% ไม่ใช่ข้อมูลหาย · แก้เป็น 1.6.1 ตามนาฬิกาคงที่ทุก 15 วิ (branch `fix/sensor-fixed-period`) ผู้ใช้ต้องแฟลชบอร์ดเอง แล้วรัน `hardware_report.js` ซ้ำหลังผ่านไป ≥ 1 ชม. ต้องได้ ~240 ค่า/ชม. (ครบ ≥ 99%)**
  - เจอ `sht4x at 0x44` (ของแท้) อ่าน ~26 °C / 72 %RH ทุก ~16 วิ ส่งถึง server ใน ~1.4 วิ
  - ต่อสาย: แดง = 3V3 · ดำ = GND · **เขียว = GPIO11 (SDA)** · **เหลือง = GPIO12 (SCL)** · ไม่มีตัวต้านทาน ใช้ pull-up ในชิป + I2C 50 kHz (ถ้าอ่านพลาดบ่อย ให้ใส่ 4.7 kΩ)
  - ตรวจรุ่นชิปเอง (SHT4x/SHT3x 0x44/0x45, AHT 0x38, HTU21 0x40) · ส่งรุ่น/serial ขึ้น heartbeat
  - watchdog 180 วิ · server ไม่ตอบ 15 นาที → รีสตาร์ต Wi-Fi · 30 นาที → รีบูต
  - **heater (เฉพาะ SHT4x):** RH ≥ 95% นาน 10 นาที → ให้ความร้อน 200 mW 1 วิ แล้วพัก 90 วิ (ไม่อ่านค่าช่วงนี้) · ทำซ้ำได้ทุก 10 นาที · รีเซ็ตเมื่อ RH < 90% · ทดสอบแล้ว (ตอนแรกพัก 30 วิ ยังมีความร้อนค้าง เลยเพิ่มเป็น 90 วิ)
- รอบกล้องในหน้า Devices ตอนนี้ยังเป็น **60 วิ** (ต้องเปลี่ยนเป็น 15 วิก่อนซ้อม)

## 7. คำสั่งที่ใช้บ่อย

ทุกสคริปต์อยู่ใน `backend_node/scripts/` ต้องมี `backend_node/.env` (ค่า `DATABASE_URL` ฯลฯ) · ถ้าต่อฐานข้อมูลช้า/timeout ให้ใช้ **hotspot มือถือ**

| งาน | สคริปต์ |
|---|---|
| รายงานซ้อม (ภาพครบไหม ประมวลผลกี่วิ) | `rehearsal_report.js` |
| หลักฐานฮาร์ดแวร์ (uptime, ความครบ, heater) — ใช้ `--json` เก็บผล | `hardware_report.js` |
| ดึงภาพที่เก็บไว้ลงเครื่อง | `download_collected.js` |
| ลบภาพบน Storage **หลังตรวจสำเนาแล้วเท่านั้น** | `free_collected.js` |
| เทียบกับวิดีโอ ตามรอบถ่าย | `compare_video.js` (+ `docs/templates/video_annotation_template.csv`) |
| เทียบเซ็นเซอร์กับเครื่องอ้างอิง | `compare_sensor.js` (+ `docs/templates/reference_readings_template.csv`) |
| วัดผลโมเดล | `eval_counts.js` |
| คัดลอกโค้ดติดตามวัวไปหน้าเว็บ | `sync_browser_tracking.js` |

วิธีใช้ (argument ทั้งหมด) เขียนไว้ที่หัวไฟล์ของแต่ละสคริปต์ · ตัวอย่าง: `node backend_node/scripts/hardware_report.js --device ESP32-S3-01 --from "2026-12-07 08:00" --to "2026-12-07 16:00" --json out.json`

อ่าน Serial ของบอร์ด:
```bash
P=$(ls /dev/cu.usbmodem* | head -1); stty -f $P 115200 raw -echo; cat $P
```

**ชื่อคีย์ที่ต้องมี (ห้ามพิมพ์ค่า):**
- `backend_node/.env`: `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (สิทธิ์สูงสุด ห้ามส่งให้ใคร ห้ามใส่หน้าเว็บ), `SECRET_KEY` (ในเครื่องต่างจากบน Render แล้ว), `CAMERA_SECRET_KEY`, `INTERNAL_API_KEY`, `FRONTEND_URL`, `PORT`
- `firmware/cowcare_sensor/secrets.h` (คัดจาก `secrets.h.example`): Wi-Fi, server, device key/serial, กล้อง (host/user/pass), ขา SHT

## 8. ตัวเลขโมเดลที่ต้องพูดให้ตรง

- mAP50 0.720 / recall 0.79 มาจากชุดทดสอบ**คอกเดียวกับชุดฝึก** และ 22% เป็นภาพเกือบซ้ำ → ห้ามเรียกว่าความแม่นในฟาร์มจริง
- ตัดภาพซ้ำออก: recall ~0.72 · กลางวัน ~0.68 · วัวตัวเล็กในภาพ (กว้าง < 6% ของเฟรม) recall 0.27–0.34
- เมื่อตรวจเจอ ท่าถูกเกือบหมด (นอน 99%, กิน 97%, ยืน 92%) ปัญหาหลักคือ**ตรวจไม่เจอ**
- ยังไม่มีภาพจากฟาร์มจริงเลย → ตัวเลขจริงต้องมาจากภาพวันที่ 6–7 ธ.ค. (ตีกรอบ ≥ 100 ภาพ)

## 9. กับดักที่เคยเจอ

- **ทดสอบหน้าเว็บในเครื่องแล้วยิงไป server จริง:** ค่าคงที่ใน `frontend/app/API/baseAPI.js` บางตัวชี้ Render เสมอ → ใช้ `frontend-test` + stub API และเช็ก network ว่าทุก `/api/` ไป localhost ก่อนใส่ token
- **พอร์ต Serial busy:** ปิด Serial Monitor ใน Arduino IDE ก่อนแฟลช
- **Serial เงียบ:** ต้องแฟลชด้วย `CDCOnBoot=cdc`
- **คิวในกล่องอยู่รอดการดับไฟ/แฟลชใหม่:** ค่าที่วัดในบ้านอาจถูกส่งขึ้นหลังติดตั้งที่ฟาร์ม → วันติดตั้งให้ผู้ใช้ลบข้อมูลทดสอบด้วย farm id + เวลาติดตั้ง (ผู้ใช้รัน SQL เอง: SELECT ดูก่อน แล้วค่อย DELETE ใน BEGIN/COMMIT)
- **วันติดตั้งต้องทำด้วย:** แก้อำเภอ/จังหวัดของฟาร์ม, เช็ก IP กล้องในวงแลนฟาร์ม, ถามเวลารีดนม/ให้อาหาร
- **งานของเพื่อน:** ก่อน merge ให้เช็ก `node --check`, conflict marker, สิทธิ์ของ route ใหม่ และคำอ้างที่ไม่จริง
