## 1. หลักการทำงาน

1. **ทำทีละ 1 งานเขียนโค้ด** (+ งานรันเบื้องหลังได้ 1 งาน เช่น ฝึกโมเดล) งานละ 1 branch แตกจาก main ล่าสุด
2. **ทุกงานมีเกณฑ์จบที่วัดได้** เขียนไว้ก่อนเริ่ม ไม่ใช่ "ดูดีแล้ว"
3. **กำหนดเวลา (timebox):** งานเกินเวลา 50% → หยุดทบทวน: ตัดขอบเขต / เลื่อน / ขอความช่วยเหลือ
4. **ฐานข้อมูลจริง:** Claude อ่านอย่างเดียว การแก้ schema เขียนเป็นไฟล์ migration → คุณรันใน Supabase → Claude ตรวจแบบอ่านอย่างเดียว
5. **ทดสอบในเครื่องไม่ยิงเว็บจริง:** ใช้ stub API บน localhost และลบ token ทดสอบทุกครั้ง
6. **ทบทวนประจำสัปดาห์ (วันศุกร์):** ทำอะไรเสร็จ, ตัวเลขเทียบเกณฑ์, ความเสี่ยงใหม่, ปรับแผน
7. **ทุกตัวเลขในเปเปอร์มีสคริปต์ใน repo รันซ้ำได้**

## 2. ตรวจก่อนเริ่ม / ตรวจหลังจบ (ใช้กับทุกงาน)

### ตรวจก่อนเริ่ม (Start check)
- [ ] main ล่าสุด, branch ใหม่, ไม่มีงานค้างที่ทับไฟล์เดียวกัน
- [ ] เขียนขอบเขต + เกณฑ์จบที่วัดได้ของงานนี้ลงในแผน
- [ ] วัดค่าเริ่มต้น: เทสต์ทั้งหมดผ่าน (`backend_node/scripts/test_*.js`), build ผ่าน, ตัวเลขเดิมที่จะเปรียบเทียบ (ถ้ามี)
- [ ] ของที่ต้องใช้พร้อม: ข้อมูล / อุปกรณ์ / การตัดสินใจ
- [ ] ตั้งกำหนดเวลา

### ตรวจหลังจบ (End check = Definition of Done)
- [ ] ผ่านเกณฑ์จบทุกข้อ (มีตัวเลขหรือหลักฐาน)
- [ ] เทสต์เดิมผ่านทั้งหมด + มีเทสต์ใหม่สำหรับส่วนที่แก้
- [ ] build หน้าเว็บผ่าน ไม่มีไฟล์เกิน 25 MiB (ข้อจำกัด Cloudflare)
- [ ] งานหน้าเว็บ: ตรวจในเบราว์เซอร์ทั้งจอคอม + มือถือ, console ไม่มี error, network อยู่ใน localhost
- [ ] อ่าน diff ทบทวนเอง (งานใหญ่ใช้ code review เพิ่ม)
- [ ] อัปเดตเอกสาร / README / แผนนี้
- [ ] commit บน branch → คุณ merge + push
- [ ] **หลัง deploy:** เปิดเว็บจริงตรวจ (คุณ) + ดู log Render ไม่มี error → อัปเดตสถานะในแผน

### ตรวจระหว่างวันเก็บข้อมูล (ทุก 30 นาที)
- [ ] กล่องเซ็นเซอร์ออนไลน์ ค่าเข้า ~4 ค่า/นาที
- [ ] ภาพเข้า ~1 ภาพ/นาที และเก็บภาพครบทุกภาพ
- [ ] วัวเป้าหมายยังเป็นตัวเดิม (ดูแถบภาพยืนยัน) ถ้าสลับ → แก้ตัวทันที
- [ ] log Render ไม่มี error / ไม่ตอบ "ยุ่ง" ติดกัน

## 4. แผนตามระยะ

### ระยะ 0: ทำให้นิ่งและวัดจุดเริ่มต้น (20 พ.ย.) ✅
- รวม `data/cbvd5-yolo` + งาน LSTM backtest จาก `codex/finalize-hackathon-submission` ไว้ใน branch `chore/phase0-stabilize`
- เทสต์ 9/9 ผ่าน, build ผ่าน (15 MB), API ตอบ 0.28 วิ (v3.1.0), หน้าเว็บตอบปกติ
- ฐานข้อมูล 25 MB, Storage 78 MB (โมเดล 77.9 MB)
- **ค้าง:** คุณ merge + push branch นี้

### ระยะ 1: เตรียมดูหน้างาน (21–24 พ.ย.)
1. **ปลุกกล่องเซ็นเซอร์:** เสียบไฟ แฟลช firmware 1.5.0 เช็กว่าข้อมูลเข้าและเหตุการณ์ "ขาดการติดต่อ" ปิดเอง
2. **ซ้อมกล้องทุก 1 นาทีอย่างน้อย 1 ชม.** บนเซิร์ฟเวอร์ฟรี: วัดเวลาประมวลผลต่อภาพจริงบน Render (ตอบคำถามเรื่องอัปเกรด)
3. **โหมดเก็บภาพทุกภาพ** ช่วงเวลาที่กำหนด (ใช้ทั้งวันดูหน้างานและวันเก็บข้อมูล) — ต้องมี migration ให้คุณรัน
4. **รายการตรวจหน้างาน 1 หน้า:** จุดติดกล้อง ความสูง มุม ระยะถึงวัว ย้อนแสง ไฟฟ้า สัญญาณเน็ต/hotspot จำนวนวัวในคอก การติดเบอร์หู
5. **D1 เอกสาร**
- **เกณฑ์จบ:** กล่องส่งข้อมูลต่อเนื่อง ≥ 1 ชม., กล้องทุก 1 นาทีเข้าครบ ≥ 95%, รู้เวลาประมวลผลต่อภาพบน Render, มีรายการตรวจพิมพ์พร้อม

### วันดูหน้างาน (≈ 25 พ.ย.)
- ทำตามรายการตรวจ ถ่ายรูปจุดติดตั้ง
- ถ้าลองอุปกรณ์ได้: เปิดโหมดเก็บภาพทุกภาพ เก็บ **ภาพจากมุมกล้องจริง 50–100 ภาพ** (กลางวัน ช่วงเวลาต่างกัน)
- **เกณฑ์จบ:** รู้จุดติดกล้องที่ใช้จริง, ได้ภาพจากคอกไทย, รู้ว่าเน็ตใช้ได้หรือต้องใช้ hotspot

### ระยะ 2: สร้างให้พร้อมวันเก็บข้อมูล (26 พ.ย.–4 ธ.ค.)
1. **ตรวจความแม่นด้วยภาพคอกไทย:** ตีกรอบภาพจากวันดูหน้างาน → วัดโมเดลรุ่น 1 (และรุ่น 2 ถ้ามี) → ตัวเลขแรกจากฟาร์มจริงสำหรับเปเปอร์
2. **farm_detail ติดตามวัว 1 ตัว:**
   - แสดง **เลขวัว (เบอร์หู/ชื่อ)** บนกรอบ ไทม์ไลน์ และ CSV (ฐานข้อมูลมี `tb_cows.tag_id` ผูกกับเป้าหมายอยู่แล้ว)
   - แถบภาพยืนยันตามเวลา + กรอบวัวเป้าหมาย
   - แก้ตัวกลางทาง (คลิกเลือกใหม่ → คำนวณย้อนหลังใหม่)
   - บอกความมั่นใจของการติดตาม + ทำให้ผลนิ่งด้วยภาพติดกัน
   - ส่งออก CSV
   - เก็บกรอบวัวทุกตัวเบื้องหลัง แสดง/ส่งออกเฉพาะวัวเป้าหมาย ✅ (ยืนยันแล้ว)
3. **Simulator:** ติดตามวัว 1 ตัวบนวิดีโอทุก 1 นาที ด้วยโค้ดเดียวกับเซิร์ฟเวอร์ (แสดงเลขชั่วคราวของวัวทุกตัวเพื่อช่วยเลือก) + โหมดวัดความแม่นด้วยไฟล์คำตอบ
4. **โมเดลรุ่น 2 (เบื้องหลัง):** ชุดรวม CBVD-5 → ฝึก → วัดกับกล้องที่กันไว้ + ภาพคอกไทย
- **เกณฑ์จบ:**
  - ติดตามบนเบราว์เซอร์ = เซิร์ฟเวอร์ (เทสต์อัตโนมัติ)
  - farm_detail: แก้ตัวแล้วไทม์ไลน์ถูก, CSV ตรงกับกราฟ, มีเลขวัวทุกจุด
  - เลือกโมเดลสำหรับวันจริงจากผลบนภาพคอกไทย (ใช้รุ่น 2 เฉพาะเมื่อดีกว่ารุ่น 1 บนภาพคอกไทย)

### ระยะ 3: ซ้อมใหญ่ + ด่านไป/ไม่ไป (7–9 ธ.ค.)
- ซ้อม 4–6 ชม. ด้วยอุปกรณ์จริง (ที่ฟาร์มหรือที่บ้าน) ทุก 1 นาที
- สำรองฐานข้อมูลก่อนวันจริง
- **ด่านไป/ไม่ไป:** ไม่หลุดเกิน 15 นาที, ภาพเข้าครบ ≥ 95%, ติดตามวัวถูกตัว ≥ 90% ของภาพที่สุ่มตรวจ

### วันเก็บข้อมูล (≈ 8–11 ธ.ค., รออาจารย์ยืนยัน)
- 4–6 ชม., กล้องทุก 1 นาที (240–360 ภาพ), เซ็นเซอร์ทุก 15 วิ, เก็บภาพทุกภาพ
- คลิกเลือกวัวเป้าหมาย + ใส่เบอร์หู, ตรวจทุก 30 นาที (ข้อ 2)
- จดเหตุการณ์หน้างาน (ให้อาหาร รีดนม เปิดพัดลม) เพื่อใช้อธิบายผล

### ระยะ 4: วิเคราะห์ + ตัวเลขเปเปอร์ (12–20 ธ.ค.) + D2
1. ตีกรอบสุ่ม ≥ 100 ภาพจากวันจริง → ความแม่นตรวจจับ + ความแม่นการติดตามวัวเป้าหมาย
2. ไทม์ไลน์วัวตัวนี้ vs THI (เชิงพรรณนา), ความครบถ้วนของข้อมูล, เวลาประมวลผล
3. สคริปต์ทุกตัวเลขอยู่ใน repo
- **เกณฑ์จบ:** ตัวเลขครบตามข้อ 6 และรันซ้ำได้

### ระยะ 5: เอกสารสุดท้าย (21–26 ธ.ค.) + D3 → อาจารย์ส่งก่อน 31 ธ.ค. (เผื่อ 4–5 วัน)

## 5. เก็บภาพได้ถี่แค่ไหนถ้าไม่อัปเกรด Render

- เซิร์ฟเวอร์ฟรี (CPU 0.1) ประมวลผลภาพละประมาณ **24 วินาที** (วัดตอนพัฒนา ต้องวัดซ้ำบน Render จริงในระยะ 1)
- ถ้าภาพมาระหว่างกำลังประมวลผล เซิร์ฟเวอร์ตอบ "ยุ่ง" และบอกกล่องให้ส่งรอบถัดไป (ไม่ล่ม)
- **ถี่สุดตามทฤษฎี ~2 ภาพ/นาที, ที่แนะนำ 1 ภาพ/นาที** → 4–6 ชม. = **240–360 ภาพ** พอสำหรับเปเปอร์ 1 วัน
- เซ็นเซอร์ทุก 15 วิไม่ได้รับผลกระทบ
- **ตัดสินใจจากการซ้อมในระยะ 1:** ถ้าประมวลผล > 40 วิ/ภาพ หรือ "ยุ่ง" > 10% → อัปเกรดเฉพาะเดือนนั้น หรือรัน backend บน laptop ที่ฟาร์ม

- **สำรองฐานข้อมูล + ดาวน์โหลดภาพวันจริงเก็บเครื่อง** หลังวันเก็บข้อมูลทันที
- Migration: ไฟล์ SQL ใน `backend_node/migrations` → คุณรัน → ตรวจอ่านอย่างเดียว → จดในแผน
- โมเดลรุ่น 2 ขึ้น Storage +~80 MB (เก็บรุ่น 1 ไว้ย้อนกลับ)

## 9. นวัตกรรม (จุดขาย)

**จุดขายหลัก:** ระบบต้นทุนต่ำที่รวม (1) เซ็นเซอร์ THI ในคอกจริง (2) พยากรณ์ THI ที่ปรับตามคอก และ (3) **ติดตามพฤติกรรมวัวรายตัวด้วยคลิกเดียว** จากกล้องวงจรปิดทั่วไป พร้อมเลขประจำตัววัว

**ไอเดียหลังส่งเปเปอร์ (ที่จอดงาน):** ดัชนีความไวต่อความร้อนรายตัว, เตือนล่วงหน้าเฉพาะตัว, วงจรเลือกภาพที่โมเดลไม่มั่นใจมาตีกรอบก่อน
