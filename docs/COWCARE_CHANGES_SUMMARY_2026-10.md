# CowCare AI: สรุปสิ่งที่เพิ่มและตัดออกจากระบบ

อัปเดต: 24 ตุลาคม 2569 (2026-10-24)
สถานะ: ทดสอบในบ้านแล้ว ยังไม่ได้ติดตั้งที่ฟาร์มจริง

---

## 1. สิ่งที่เพิ่มเข้ามา

### 1.1 กล่องเซ็นเซอร์ (firmware 1.4.1)
- ส่งข้อมูลแบบ HTTPS ที่ตรวจใบรับรองจริง
- บังคับใช้ device key: กล่องที่ไม่มี key ส่งข้อมูลเข้าระบบไม่ได้
- รายงานสถานะกล่องทุก 5 นาที (heartbeat): ปกติ / เซ็นเซอร์เสีย / ข้อมูลค้างส่ง / ออฟไลน์
- เก็บข้อมูลไว้ในบอร์ดเมื่อเน็ตหลุด แล้วทยอยส่งเมื่อเน็ตกลับมา
- สคริปต์ตรวจรุ่นเซ็นเซอร์ (อ่านอย่างเดียว): พบว่าเป็นตระกูล XY-MD02 ชิป SHT20 (±0.3°C / ±3% RH)

### 1.2 กล้อง
- บอร์ดดึงภาพจากกล้อง Dahua ทุก 10 นาที → เซิร์ฟเวอร์ใช้ YOLO26m ONNX (`best.onnx`) นับวัวแยกตาม 4 ท่า (`drinking`, `feeding`, `lying down`, `standing`)
- เก็บโมเดลใน Supabase แบบ private และตรวจไฟล์ด้วย SHA-256
- เก็บภาพตัวอย่างชั่วโมงละ 1 รูป พร้อมไฟล์ JSON ผลของโมเดล (จำนวนแต่ละท่าและกรอบ) เพื่อใช้นับเทียบและทำ dataset โรงเรือนไทย
- ตัดกรอบซ้อนโดยไม่ดูท่า (Class-Agnostic NMS: `conf = 0.25`, `iouThr = 0.7`, 1 ตัว = 1 กรอบ) แก้ปัญหานับวัวซ้ำ
  - ทดสอบกับภาพชุดทดสอบ 203 ภาพ: วัวที่ถูกนับซ้ำลดจาก 11 คู่ เหลือ 0
- เข้ารหัสรหัสผ่านกล้อง (AES-256-GCM) และไม่เก็บรหัสไว้ในลิงก์ RTSP
- หน้า admin เพิ่ม/แก้ไขกล้องได้ หน้าฟาร์มแสดงสถานะกล้องจากภาพจริง

### 1.3 THI และเกณฑ์ไทย
- สูตร THI ของ NRC (1971) และเกณฑ์โคลูกผสมไทยจาก THI เฉลี่ยรายวัน 74 / 76 / 82 พร้อมอ้างอิงงานวิจัยที่ตรวจสอบได้
- วิธีคำนวณชุดเดียวกันทั้งระบบ (`heatMetrics.js`, `heatStress.js`):
  - ความครบถ้วนของข้อมูล
  - ระดับความเครียดจาก THI เฉลี่ยรายวัน
  - ชั่วโมงกลางคืนที่วัวได้พักจากความร้อน (`THI < 74` ช่วง 22:00–06:00 น.)
  - จำนวนวันเครียดติดต่อกัน (THI เฉลี่ยรายวัน `>= 76` เฉพาะวันที่มีข้อมูลอย่างน้อย 12 ชม.)
- แสดงสูตร วิธีนับ ข้อควรทราบ และแหล่งอ้างอิงในหน้าเว็บ
- คำแนะนำตามบริบทไทย:
  - ช่วงร้อนและช่วงเย็นคำนวณจากข้อมูล 72 ชม. ของฟาร์มเอง
  - ความชื้นตั้งแต่ 75% ขึ้นไป แนะนำราดน้ำร่วมกับพัดลม แทนการพ่นหมอก

### 1.4 ระบบพยากรณ์ THI ล่วงหน้า 3 วัน (`hybrid-ecmwf-bias-v1`)
- เปลี่ยนจากการใช้ค่าเฉลี่ย 72 ชม. ย้อนหลังคงที่ทั้ง 3 วัน เป็นการดึงพยากรณ์อากาศรายชั่วโมงจาก Open-Meteo ECMWF (`ecmwf_ifs025` และถอยกลับเป็น `best_match` เมื่อ ECMWF ขัดข้อง) ณ พิกัดฟาร์ม
- หักลบค่าเพี้ยนมัธยฐานแยกตามระยะล่วงหน้า (+1 / +2 / +3 วัน) ที่เรียนรู้จากเซ็นเซอร์จริงของฟาร์มในช่วง 3–14 วันที่ผ่านมา (ใช้เฉพาะวันที่ข้อมูลครบอย่างน้อย 20 ชม. และช่วงกลางวัน 10:00–17:00 น. ขาดไม่เกิน 1 ชม. โดยจำกัดค่าปรับไม่เกิน ±6 THI)
- กรณีฟาร์มมีข้อมูลครบไม่ถึง 3 วัน และใช้โมเดล ECMWF ในจังหวัดภาคเหนือ จะใช้ค่าเพี้ยนระดับภูมิภาคจากสถานีสนามบินเชียงใหม่ (`-1.41 / -1.37 / -1.32` THI) ส่วนกรณีไม่มีพิกัดหรือเรียก API ไม่สำเร็จจะถอยกลับไปใช้ค่าเฉลี่ย 72 ชม. (`baseline_72h_mean`) พร้อมแจ้งสาเหตุใน `fallback_reason`
- ผลทดสอบย้อนหลัง (backtest) กับข้อมูลจริงสถานีตรวจอากาศสนามบินเชียงใหม่ (WMO 48327) จำนวน 354 วัน (19 ธ.ค. 2024 – 7 ธ.ค. 2025) วัดความคลาดเคลื่อนเฉลี่ยสัมบูรณ์ (MAE) ของ THI เฉลี่ยรายวันล่วงหน้า +1 / +2 / +3 วัน:
  - ค่าเฉลี่ย 72 ชม. ย้อนหลัง: `1.10 / 1.38 / 1.56`
  - ECMWF ดิบ (ไม่ปรับค่าเพี้ยน): `1.34 / 1.32 / 1.35`
  - ECMWF + ปรับค่าเพี้ยน 14 วัน (เฉพาะวันทดสอบที่มีประวัติครบ ≥ 9 วัน): `0.69 / 0.78 / 0.88` (ทำนายระดับความเสี่ยงตรง `94% / 93% / 92%`)
  - ECMWF + ปรับค่าเพี้ยน 3 วัน: `0.80 / 0.92 / 1.07`
  - โมเดล GRU (1,212 พารามิเตอร์ เฉลี่ย 3 seed): `0.88 / 0.91 / 0.91` (แพ้วิธี ECMWF + ปรับค่าเพี้ยน จึงยังไม่เปิดใช้โมเดลตระกูล LSTM/GRU จนกว่าจะมีข้อมูลในโรงเรือนจริงหลายเดือน)

### 1.5 หน้าเกษตรกร
- ออกแบบใหม่ทั้งหมด มี 4 หน้า: วันนี้ / ย้อนหลัง / แจ้งเตือน / ฉัน
- เช็กลิสต์บันทึกการดูแลประจำวันแบบแตะเลือก (`tb_farmer_daily_actions`) โดยไม่ต้องพิมพ์กรอกข้อมูลรายวัน
- ปุ่มโทรหาสัตวแพทย์หรือสหกรณ์ (แสดงเฉพาะเมื่อฟาร์มตั้งเบอร์โทรศัพท์จริงไว้)
- รายการช่วงที่วัวเครียด ช่วงที่เซ็นเซอร์ขาดหาย ระบบอ่านออกเสียงช่วยเหลือ และหน้าต่างยืนยันก่อนออกจากระบบ

### 1.6 หน้า admin
- การ์ดความครบถ้วนของข้อมูล, ชั่วโมงกลางคืนได้พัก และจำนวนวันเครียดติดต่อกัน
- สถานะสุขภาพกล่องในหน้าอุปกรณ์
- ช่องพิกัดฟาร์ม (`latitude`, `longitude`), เบอร์สัตวแพทย์, ชนิดหลังคา (ไม่บังคับ) และเวลารีดนม/ให้อาหาร
- สมุดสหกรณ์แสดงความครบถ้วนของข้อมูล
- การ์ดเปรียบเทียบสภาพอากาศในโรงเรือนกับภายนอก (`outdoorWeather.js`):
  - ใช้พิกัดฟาร์มที่กรอกไว้เป็นอันดับแรก ถัดไปใช้จุดกึ่งกลางอำเภอ (เฉพาะเมื่ออำเภอนั้นอยู่ในจังหวัดของฟาร์ม) หรือจุดกึ่งกลางจังหวัด (ไม่มีการเดาข้ามจังหวัดหรือใช้ค่าเริ่มต้นสระบุรี)
  - เปรียบเทียบค่าเฉลี่ยรายชั่วโมงย้อนหลัง 72 ชม. ในช่วงบ่าย (12:00–16:59 น.) โดยเผื่อความคลาดเคลื่อนของโมเดลสภาพอากาศ ±2°C แสดงผลต่างปัจจุบันเฉพาะเมื่อข้อมูลเซ็นเซอร์ไม่เก่าเกินกำหนด และแสดงเครดิต Open-Meteo (CC BY 4.0)
- การจัดการผู้ใช้และรหัสผ่าน:
  - จำกัดการสร้างบัญชีใหม่ (`POST /api/auth/register`) ให้ทำได้เฉพาะ Admin เท่านั้น
  - Admin เป็นผู้กำหนดรหัสผ่านเมื่อสร้างผู้ใช้ และสามารถตั้งรหัสผ่านใหม่เมื่อผู้ใช้ลืมรหัสได้ (บังคับรหัสผ่านอย่างน้อย 6 ตัวอักษร และห้ามตรงกับเบอร์โทรศัพท์)

### 1.7 ความปลอดภัยและการแก้บั๊ก
- ปิด route กล้องและระบบ (`/api/Admin/cctv/*`, `/api/Admin/system/*`) ที่เคยเปิดสาธารณะ ให้ต้องตรวจ token ของ Admin (หรือ `X-Internal-Key` สำหรับบริการภายใน)
- ลบ route `POST /api/farmer/friend-bridge/test` ที่เปิดให้เซิร์ฟเวอร์เรียก URL ใดก็ได้โดยไม่ต้องล็อกอิน (SSRF)
- จำกัดตัวสลับเซิร์ฟเวอร์สำรอง (backend switcher) ให้ทำงานและแสดงผลเฉพาะเมื่อเปิดจาก `localhost` หรือ LAN เท่านั้น ป้องกันการหลอกให้ส่งรหัสผ่านไปเซิร์ฟเวอร์อื่นบนเว็บจริง
- ไม่สร้างบอร์ด `ESP32-S3-01` อัตโนมัติเมื่อตารางอุปกรณ์ว่าง และไม่ตั้งสถานะบอร์ดเป็น `online` ปลอมตอนผูกฟาร์ม (สถานะมาจากข้อมูลเซ็นเซอร์และ heartbeat จริงเท่านั้น)
- ลบการสร้างตารางอัตโนมัติ (`CREATE TABLE`) ตอนเปิดเซิร์ฟเวอร์ใน `farmer.js` และย้ายไปไว้ในไฟล์ migration
- ตั้งค่า `app.set('trust proxy', 1)` เพื่อให้ได้ IP จริงหลัง Render proxy และตัด origin ของ tunnel ชั่วคราว (`trycloudflare`, `ngrok`, `loca.lt`) ออกจาก CORS
- แก้กราฟย้อนหลังให้ดึงข้อมูลครบ 24 ชม., เข้ารหัสรหัสกล้องสม่ำเสมอ และแก้หน้าแก้ไขฟาร์มให้เลือกบอร์ดที่ผูกอยู่เดิมขึ้นมาแสดงอย่างถูกต้อง

## 2. สิ่งที่ตัดออก (ข้อมูลไม่จริงหรืออ้างเกินจริง)

| ตัดออก | เหตุผล |
|---|---|
| ตัวเลขสมมติในหน้ากล้อง, แบตเตอรี่ และสัญญาณของอุปกรณ์ | ไม่ได้มาจากอุปกรณ์จริง |
| ป้าย "Certified" และเกรดในสมุดสหกรณ์ | ยังไม่มีหน่วยงานไหนรับรอง |
| ตัวเลขความแม่นของ LSTM (96.08%), mAP (76.88%), MOTA (81.2%), การตรวจท่าหอบ และสมการน้ำนมลด/มีเทน | ไม่มีในโค้ดจริงหรือไม่มีผลทดสอบรองรับ |
| งานวิจัยปี 2026 ที่ตรวจสอบไม่พบ (`Hasan 2026`, `Mulajkar 2026`, `Abdourhamane 2026`, `Onan-Martinez 2026`, `Mylostyvyi 2026`) | หาแหล่งอ้างอิงจริงมายืนยันไม่ได้ |
| คำว่า SHT40 | เซ็นเซอร์จริงคือ SHT20 (XY-MD02) |
| การอ้างชื่อมหาวิทยาลัยแม่โจ้ | ไม่มีความร่วมมือจริง |
| ค่าเริ่มต้นฟาร์มที่ระบบใส่ให้เอง (สระบุรี / มวกเหล็ก / สูง 2.7 ม. / สังกะสี / พัดลม) | เขียนทับข้อมูลจริงทุกครั้งที่แก้ไขฟาร์ม |
| เบอร์สัตวแพทย์เริ่มต้นปลอม (`080-000-0000`) | หากไม่ได้ตั้งเบอร์จริงไว้ ระบบจะไม่แสดงปุ่มโทร |
| ปุ่มขอความช่วยเหลือฉุกเฉิน SOS (`tb_farmer_sos_alerts`) | ข้อความแจ้งว่าเจ้าหน้าที่จะโทรกลับแต่ยังไม่มีระบบแจ้งเตือนไปหาเจ้าหน้าที่จริง |
| สมุดบันทึกน้ำนมและสุขภาพรายวันฝั่งเกษตรกร (`tb_farmer_daily_logs`, หน้า `/Farmer/logs`) | ขัดหลักการ "เกษตรกรไม่ต้องกรอกข้อมูลรายวัน" |
| การคำนวณอากาศภายนอกซ้ำในหน้าเว็บ (`outdoorWeather.ts`) และเกณฑ์ `1.5–2.0°C` ที่ไม่มีอ้างอิง | คำนวณที่ backend จุดเดียว และใช้เกณฑ์เปรียบเทียบช่วงบ่าย 72 ชม. เผื่อความคลาดเคลื่อนโมเดล ±2°C |
| การสร้างอุปกรณ์อัตโนมัติและสถานะ `online` ปลอมตอนสร้างฟาร์ม | ทำให้สถานะอุปกรณ์ไม่ตรงความจริง |
| การปิดตรวจใบรับรอง HTTPS เป็นค่าปกติ | ไม่ปลอดภัย เหลือไว้เป็นสวิตช์ฉุกเฉินเท่านั้น |
| ช่องกรอกสายเลือดวัว | ไม่มีใครกรอกจริง ใช้เกณฑ์โคลูกผสมไทยค่าเดียว |
| ฟีเจอร์ยื่นประกัน | ยังไม่มีบริษัทประกันรับข้อมูลแบบนี้ |
| การตัดกรอบซ้อนแบบแยกตามท่า | ทำให้นับวัวตัวเดียวซ้ำ |

## 3. ตกลงไว้ว่าจะทำทีหลัง
- วัดความแม่นพยากรณ์ในโรงเรือนจริงหลังติดตั้ง 2 สัปดาห์ (เทียบกับค่า THI เฉลี่ยรายวันจากเซ็นเซอร์ฟาร์ม)
- หน้านับเทียบความแม่นของโมเดลกล้อง และหน้าวิเคราะห์ % วัวนอนเทียบกับ THI (หลังติดตั้ง 2–3 สัปดาห์)
- แจ้งเตือนผ่าน LINE รายฟาร์ม (ทำในงานแฮ็กกาธอน)
- Gemini
- โมเดลตระกูล LSTM/GRU เมื่อมีข้อมูลในโรงเรือนจริงสะสมหลายเดือน
- ระบบสั่งเปิดพัดลมหรือระบบทำความเย็นอัตโนมัติ

## 4. ข้อจำกัดที่ต้องรู้
- ระบบทั้งหมดทดสอบในบ้าน ยังไม่ได้ติดตั้งและวัดผลในโรงเรือนจริง
- ความแม่นของเซ็นเซอร์ใช้ค่าตามสเปก SHT20 (THI คลาดได้ประมาณ ±0.7) ยังไม่ได้เทียบกับเครื่องวัดอ้างอิง
- ความแม่นของระบบพยากรณ์ 3 วัน (`MAE 0.69 / 0.78 / 0.88`) วัดกับสถานีตรวจอากาศกลางแจ้งสนามบินเชียงใหม่ (WMO 48327) ยังไม่ใช่ข้อมูลในโรงเรือนจริง
- โมเดล YOLO26m เทรนจากภาพต่างประเทศ ผลกับภาพชุดทดสอบ 203 ภาพ:
  - พลาดวัวประมาณ 21%
  - จำนวนวัวนอนคลาดเฉลี่ย 0.47 ตัวต่อภาพ
  - ความแม่นในโรงเรือนไทยยังต้องวัดหลังติดตั้ง
