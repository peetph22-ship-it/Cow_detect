# CowCare AI: ตั้งค่าเครื่องสำหรับคนใหม่ (เน้นงานฝั่งเกษตรกร)

คู่มือนี้สำหรับคนที่เพิ่ง clone โปรเจกต์ และจะทำงานหน้าเกษตรกร (`/Farmer`)

---

## 0. กฎสั้นๆ ก่อนเริ่ม

- **ห้าม commit `.env` หรือ `secrets.h`** (ถูก `.gitignore` ไว้แล้ว) ค่าลับขอจากเจ้าของโปรเจกต์ทางข้อความส่วนตัวเท่านั้น
- ทำงานใน branch ของตัวเอง เช่น `farmer/xxx` แล้วเปิด Pull Request ให้เจ้าของโปรเจกต์ review ก่อน merge เข้า `main`
- `main` ถูก deploy อัตโนมัติ: หน้าเว็บขึ้น Cloudflare Pages และ backend ขึ้น Render
- ตัวเลขที่แสดงต้องมาจากข้อมูลจริงเสมอ ถ้าไม่มีข้อมูลให้แสดงว่า "ยังไม่มีข้อมูล" ห้ามใส่ค่าสมมติ

## 1. สิ่งที่ต้องมีในเครื่อง

- Node.js 20 ขึ้นไป (เจ้าของโปรเจกต์ใช้ 24)
- Git และ VS Code

---

## 2. ทางที่ 1 (แนะนำ): ทำเฉพาะหน้าเว็บ ใช้ API จริง

เหมาะกับงานหน้าตาและการแสดงผลของหน้าเกษตรกร **ไม่ต้องใช้ค่าลับเลย**

```bash
cd frontend
npm install
cp .env.example .env
```

แก้ `frontend/.env` บรรทัดนี้:

```
NUXT_PUBLIC_NODE_API_BASE=https://cow-detect-zea6.onrender.com/api
```

จากนั้นรัน:

```bash
npm run dev
```

1. เปิด http://localhost:3000/login แล้ว login ด้วยบัญชีเกษตรกรที่เจ้าของโปรเจกต์สร้างให้ (ข้อ 5)
2. ระบบจะพาไปหน้า `/Farmer`
3. ถ้าเว็บตอบช้าตอนเปิดครั้งแรก เป็นเพราะ Render แผนฟรีหลับอยู่ รอประมาณ 1 นาที

**ทำไมทางนี้ปลอดภัย:** API ฝั่งเกษตรกรมีแค่การอ่านข้อมูล (`GET /api/farmer/me`, `/history`, `/events`) ไม่มีจุดไหนแก้หรือลบข้อมูล

### ไฟล์ของฝั่งเกษตรกร

| ไฟล์ | หน้าที่ |
|---|---|
| `frontend/app/layouts/farmer.vue` | โครงหน้า (หัว, เมนูล่าง) |
| `frontend/app/pages/Farmer/index.vue` | หน้า "วันนี้" |
| `frontend/app/pages/Farmer/history.vue` | ย้อนหลัง 7 วัน |
| `frontend/app/pages/Farmer/alerts.vue` | ช่วงเครียดและช่วงเซ็นเซอร์ขาด |
| `frontend/app/pages/Farmer/me.vue` | ข้อมูลฟาร์มและปุ่มโทรหาสัตวแพทย์ |
| `frontend/app/composables/useFarmer.js` | ดึงข้อมูลจาก API ทุกหน้าใช้ตัวนี้ |
| `frontend/app/components/common/HeatMethodNote.vue` | กล่อง "วิธีคำนวณและที่มา" |
| `DESIGN.md` | สี ฟอนต์ และแนวดีไซน์ (ให้สอดคล้องกับฝั่ง admin) |

### เวลาเรียก API ในหน้าใหม่

ใช้ `useFarmer` หรือ `getNodeApiBase()` จาก `~/API/baseAPI` และอ่านค่าใน `setup` เท่านั้น

**ห้ามใช้ค่าคงที่ `Admin` หรือ `api`** เพราะในเบราว์เซอร์ค่าเหล่านี้ชี้ไปเซิร์ฟเวอร์จริงเสมอ แม้จะตั้ง `.env` ให้ชี้เครื่องตัวเองแล้วก็ตาม

## 3. ทางที่ 2: ต้องแก้ backend ของฝั่งเกษตรกรด้วย

ใช้เมื่อหน้าเว็บต้องการข้อมูลที่ API ยังไม่มี ไฟล์ที่เกี่ยวข้อง:
- `backend_node/app/routes/farmer.js`
- `backend_node/app/services/heatMetrics.js`: ตัวคำนวณ THI ชุดเดียวของทั้งระบบ ห้ามคำนวณซ้ำเองในหน้าเว็บ

```bash
cd backend_node
npm install
cp .env.example .env
```

ใส่ค่าใน `backend_node/.env`:

| ตัวแปร | ได้จากไหน |
|---|---|
| `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_KEY` | ขอจากเจ้าของโปรเจกต์ทางข้อความส่วนตัว ได้แล้วลบข้อความทิ้ง |
| `SECRET_KEY` | **สร้างเอง ห้ามใช้ค่าเดียวกับ Render** คำสั่ง `openssl rand -hex 32` |
| ที่เหลือ | ใช้ค่าตามไฟล์ตัวอย่างได้เลย ส่วนกล้องไม่ต้องตั้ง |

รัน backend (port 4001):

```bash
npm run dev
```

แล้วแก้ `frontend/.env` ให้ชี้เครื่องตัวเอง:

```
NUXT_PUBLIC_NODE_API_BASE=http://localhost:4001/api
```

**ข้อควรระวัง: backend ในเครื่องต่อกับฐานข้อมูลจริง**
- API ฝั่งเกษตรกรอ่านอย่างเดียว ตอน login จะมีแค่การบันทึกเวลา login ล่าสุด
- **อย่ากดบันทึก แก้ หรือลบอะไรในหน้า admin ตอนรันในเครื่อง** เพราะจะเขียนลงข้อมูลจริงทันที
- ถ้าต้องเพิ่มตาราง/คอลัมน์ ให้เขียนไฟล์ SQL ใน `backend_node/migrations/` แล้วให้เจ้าของโปรเจกต์เป็นคนรัน ห้ามรันเอง
- backend ที่แก้จะใช้กับเว็บจริงได้หลัง merge และ Render deploy เสร็จแล้วเท่านั้น

## 4. หลักการของหน้าเกษตรกร

- **เกษตรกรไม่ต้องกรอกข้อมูลรายวัน** ทุกอย่างมาจากเซ็นเซอร์และกล้องอัตโนมัติ
- ภาษาไทย อ่านง่าย ตัวเลขน้อย บอกว่า "ต้องทำอะไร" มากกว่าตัวเลขดิบ
- ใช้เกณฑ์ THI โคลูกผสมไทย 74 / 76 / 82 จาก backend (`thresholds` ใน `/api/farmer/me`) ห้ามเขียนตัวเลขเกณฑ์ไว้ในหน้าเว็บเอง
- ห้ามแสดงข้อมูลส่วนตัวหรือข้อมูลอุปกรณ์ เช่น serial, IP กล้อง หรือเบอร์ของคนอื่น (API ไม่ส่งมาอยู่แล้ว ยกเว้นเบอร์สัตวแพทย์)
- ไม่อ้างสิ่งที่ระบบยังไม่ได้ทำจริง เช่น "ลดน้ำนม x กก." หรือ "รับรองโดย..."

## 5. สำหรับเจ้าของโปรเจกต์: เตรียมบัญชีให้คนใหม่

1. หน้า Admin → สมาชิกเกษตรกร (Users) → เพิ่มผู้ใช้ เลือกบทบาท "เกษตรกร (ฟาร์ม)"
2. ผูกบัญชีนั้นกับฟาร์มแบบ "ดูอย่างเดียว" (viewer) โดยรัน SQL นี้ใน Supabase → SQL Editor ไม่ต้องเปลี่ยนเจ้าของฟาร์มเดิม:

```sql
INSERT INTO tb_farm_members (id_farms, id_users, role)
SELECT 'ใส่-id-ฟาร์ม'::uuid, id_users, 'viewer'
FROM tb_users WHERE email = 'อีเมลของเพื่อน'
ON CONFLICT (id_farms, id_users) DO NOTHING;
```

3. ถ้าเพื่อนใช้ทางที่ 2 ให้ส่ง `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_KEY` ทางข้อความส่วนตัว
4. ถ้าเพื่อนเลิกช่วยงาน:
   - ลบบัญชีออก
   - เปลี่ยนรหัสผ่านฐานข้อมูลใน Supabase แล้วอัปเดต `DATABASE_URL` บน Render

## 6. ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| ข้อความ CORS ใน console | backend อนุญาตแค่ `localhost:3000` และ `3001` ให้รันหน้าเว็บด้วย port เหล่านี้ |
| login แล้วขึ้น 401 | token จากเซิร์ฟเวอร์จริงใช้กับ backend ในเครื่องไม่ได้ (และกลับกัน) เพราะ `SECRET_KEY` ต่างกัน ให้ logout แล้ว login ใหม่หลังเปลี่ยน `NUXT_PUBLIC_NODE_API_BASE` |
| หน้าเกษตรกรขึ้นว่า "บัญชีนี้ยังไม่ได้ผูกกับฟาร์ม" | บัญชียังไม่ได้ผูกกับฟาร์ม ให้เจ้าของโปรเจกต์ทำข้อ 5 ขั้นที่ 2 |
| เปิดครั้งแรกช้ามาก | Render แผนฟรีหลับอยู่ รอประมาณ 1 นาที |

## 7. การเชื่อมต่อกับหลังบ้านของเพื่อน (Connecting to Friend's Backend)

หากเพื่อนของคุณรัน backend ในเครื่องของเขา หรือบนคลาวด์/อุโมงค์เน็ต คุณสามารถเชื่อมต่อไปยังหลังบ้านของเพื่อนได้ 2 วิธี:

### วิธีที่ 1: ตั้งค่าผ่านหน้าเว็บโดยตรง (ไม่ต้องแก้โค้ด / ไม่ต้อง restart)
1. เปิดหน้าเว็บเข้าไปที่เมนู **"ฟาร์มฉัน"** (`/Farmer/me`)
2. เลื่อนลงมาที่หัวข้อ **"เชื่อมต่อหลังบ้าน (Backend Server)"**
3. เลือก **"หลังบ้านของเพื่อน"** แล้วใส่ URL ของเพื่อน เช่น:
   - วงแลนเดียวกัน: `http://192.168.1.50:4001/api`
   - คลาวด์หรือ Cloudflare Tunnel: `https://xxxx.trycloudflare.com/api`
4. กดปุ่ม **"ทดสอบ"** เพื่อเช็คว่าเครื่องเพื่อนเปิดรับหรือไม่
5. กดปุ่ม **"บันทึกและเชื่อมต่อทันที"** หน้าเว็บจะสลับไปดึงข้อมูลจากหลังบ้านเพื่อนทันที!

### วิธีที่ 2: ตั้งค่าผ่านไฟล์ `.env`
ใน `frontend/.env`:
```
NUXT_PUBLIC_NODE_API_BASE=http://<IP-เครื่องเพื่อน>:4001/api
```
แล้วรัน `npm run dev` ใหม่

*(หมายเหตุ: ระบบมีตัวตรวจและปรับโครงสร้างข้อมูลอัตโนมัติ แม้หลังบ้านของเพื่อนจะส่งฟิลด์ข้อมูลต่างไปเล็กน้อย ระบบหน้าบ้านเกษตรกรก็ยังแสดงผลได้อย่างราบรื่น)*
