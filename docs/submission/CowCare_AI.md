# CowCare AI — เฝ้าระวังความเครียดจากความร้อนของโคนมฟาร์มรายย่อยไทย

**ธีม:** 3. Agriculture & Food (พลิกโฉมการเกษตรและอาหาร)
**สถานะ:** ต้นแบบทำงานครบทั้งระบบ (เซ็นเซอร์ → cloud → หน้าเว็บ) ทดสอบในสถานที่ทดสอบแล้ว อยู่ระหว่างเตรียมติดตั้งที่ฟาร์มจริง
**เว็บต้นแบบ:** https://cow-detect.pages.dev (หน้าแรกเปิดดูได้ทันที ส่วนหน้าเกษตรกรและแอดมินต้องเข้าสู่ระบบ)
**ภาพหน้าจอจริง:** อยู่ในไฟล์ HTML ที่ส่งคู่กัน หัวข้อ 03 (หน้าเกษตรกรบนมือถือ ข้อมูลจริงจากเซ็นเซอร์ทดสอบในบ้าน)

## 1. ปัญหา

- งานวิจัยโคนมลูกผสมโฮลสไตน์ไทยพบว่าผลผลิตเริ่มได้รับผลเมื่อ THI เฉลี่ยรายวันถึง **74** (แม่โคสายเลือดโฮลสไตน์สูง ท้องที่ 3 ขึ้นไป) จุดเริ่มเครียดระดับประชากรอยู่ที่ **76** และผลกระทบชัดขึ้นเมื่อ THI ถึง **82** (Boonkum et al., 2011; 2024)
- พยากรณ์อากาศทั่วไปบอกอากาศภายนอก แต่อากาศในโรงเรือนขึ้นกับหลังคา ร่มเงา และการระบายอากาศของแต่ละคอก จึงใช้แทนกันตรงๆ ไม่ได้
- **สมมติฐานที่ใช้ออกแบบ (ยังไม่ได้สำรวจ):** ฟาร์มรายย่อยส่วนใหญ่ยังไม่มีเครื่องวัดในคอก และเกษตรกรไม่สะดวกกรอกข้อมูลทุกวัน ระบบจึงต้องทำงานเองและอ่านง่ายบนมือถือ เราจะตรวจสมมติฐานนี้กับเกษตรกรและสหกรณ์ตอนติดตั้ง

## 2. แนวทางแก้

ระบบวัดจริงในคอก คำนวณด้วยเกณฑ์งานวิจัยไทย พยากรณ์ล่วงหน้า 3 วัน และบอกว่าควรทำอะไร **โดยเกษตรกรไม่ต้องกรอกอะไรเลย**

| ส่วน | ทำอะไร |
|---|---|
| กล่องเซ็นเซอร์ในคอก | ESP32-S3 + หัววัด SHT20 (RS485) อ่านค่าทุก 2 วินาที ส่งทุก 15 วินาทีผ่าน HTTPS เน็ตหลุดเก็บในหน่วยความจำได้ราว 3 สัปดาห์แล้วส่งย้อนหลัง ส่งสัญญาณชีพกล่องทุก 5 นาที |
| คำนวณ THI | สมการ NRC (1971) เฉลี่ยทุก 5 นาที ไม่เดาค่าช่วงที่ไม่มีข้อมูล เลือกเกณฑ์ตามสายพันธุ์ของฟาร์ม |
| พยากรณ์ 3 วัน | พยากรณ์อากาศ ECMWF ที่พิกัดฟาร์ม ปรับด้วยค่าเพี้ยนที่เรียนจากเซ็นเซอร์ของคอกนั้นเอง |
| กล้อง (ข้อมูลเสริม) | ESP32 ดึงภาพนิ่งจากกล้อง IP ในคอกทุก 10 นาที YOLO26m นับวัว 4 ท่า (ยืน นอน กิน ดื่ม) เพื่อดูว่าวัวตอบสนองต่อความร้อนจริงไหม |
| หน้าเกษตรกร | ออกแบบสำหรับผู้สูงอายุบนมือถือ: สถานะคอกตอนนี้ คืนที่ผ่านมาวัวได้พักไหม ช่วงที่คอกนี้มักร้อนที่สุด พยากรณ์ 3 วัน ปุ่มโทรหาสัตวแพทย์ |
| หน้าแอดมิน/สหกรณ์ | สถานะทุกฟาร์ม สุขภาพกล่อง เหตุการณ์ความร้อนย้อนหลัง สมุดบันทึกความเสี่ยง 30 วัน |

### เกณฑ์ THI ที่ใช้ (THI เฉลี่ยรายวัน)

| ระดับ (คำที่เกษตรกรเห็น) | โคนมลูกผสมไทยทั่วไป | สายเลือดโฮลสไตน์สูง (≥ 87.5%) |
|---|---|---|
| สบายดี | < 74 | < 72 |
| เริ่มอุ่น | 74–75.9 | 72–73.9 |
| อากาศร้อน | 76–81.9 | 74–79.9 |
| ร้อนจัด | ≥ 82 | ≥ 80 |

### ตัวชี้วัดที่ระบบสรุปให้อัตโนมัติ
- **ชั่วโมงร้อน:** เวลาที่ THI ถึงระดับอากาศร้อน
- **การพักฟื้นกลางคืน (22:00–06:00):** ชั่วโมงที่ THI ต่ำกว่าระดับเริ่มอุ่นของฟาร์ม (74 สำหรับโคทั่วไป, 72 สำหรับสายเลือดโฮลสไตน์สูง) เพราะวัวที่ไม่ได้เย็นตอนกลางคืนจะสะสมความร้อนไปวันรุ่งขึ้น (แนวคิดจาก Igono et al., 1992 ส่วนค่าเกณฑ์เป็นค่าของระบบเอง)
- **วันร้อนติดกัน:** นับเฉพาะวันที่มีข้อมูลอย่างน้อย 12 ชม.
- **เหตุการณ์ความร้อน:** ร้อนต่อเนื่อง ≥ 30 นาทีนับเป็น 1 ครั้ง ไม่ใช่นับทุกค่าที่ส่งมา
- **ความครบของข้อมูล:** ถ้ากล่องหลุด ระบบบอกว่า "ไม่มีข้อมูล" ไม่สรุปว่า "ปลอดภัย"
- **คำแนะนำตามความชื้น:** ความชื้น ≥ 75% แนะนำงดพ่นหมอก ให้ฉีดน้ำที่หลังและไหล่วัวสลับกับพัดลม (Penn State Extension)

## 3. AI ในระบบ (เท่าที่ทำงานจริงตอนนี้)

### 3.1 พยากรณ์ THI ในคอกล่วงหน้า 3 วัน (hybrid ECMWF + ค่าเพี้ยนของคอก)
1. ดึงพยากรณ์ ECMWF IFS (0.25°) จาก Open-Meteo ที่พิกัดฟาร์ม แปลงเป็น THI เฉลี่ยรายวัน
2. ดึงพยากรณ์ที่ ECMWF เคยออกไว้ย้อนหลังสูงสุด 14 วัน เทียบกับค่าที่เซ็นเซอร์ในคอกวัดได้จริง (เริ่มใช้ได้เมื่อมีข้อมูลคอกครบ 3 วัน)
3. ค่าเพี้ยน = มัธยฐานของ (พยากรณ์ − ค่าจริง) แยกตามระยะล่วงหน้า ค่านี้รวมผลของหลังคา ร่มเงา และการระบายอากาศของคอกนั้นไว้ในตัว
4. พยากรณ์ในคอก = ECMWF − ค่าเพี้ยน

**ผลทดสอบย้อนหลัง** 354 วัน (19 ธ.ค. 2567 – 7 ธ.ค. 2568) กับสถานีอุตุนิยมวิทยาท่าอากาศยานเชียงใหม่ (WMO 48327) ค่าคลาดเคลื่อนเฉลี่ย (MAE หน่วย THI ยิ่งต่ำยิ่งดี):

| วิธี | +1 วัน | +2 วัน | +3 วัน |
|---|---|---|---|
| ค่าเฉลี่ย 72 ชม. ล่าสุด (วิธีพื้นฐาน) | 1.10 | 1.38 | 1.56 |
| ECMWF ดิบ | 1.34 | 1.32 | 1.35 |
| GRU (เครือข่ายประสาทเทียม เราลองแล้วไม่ใช้) | 0.88 | 0.91 | 0.91 |
| ECMWF + ค่าเพี้ยนภาคเหนือ (ใช้เมื่อมีข้อมูลคอกไม่ถึง 3 วัน) | 0.77 | 0.83 | 0.90 |
| ECMWF + ค่าเพี้ยนจากประวัติ 3–8 วัน (เพิ่งติดตั้ง) | 0.80 | 0.92 | 1.07 |
| **ECMWF + ค่าเพี้ยนจากประวัติ 9–14 วัน (ใช้งานปกติ)** | **0.69** | **0.78** | **0.88** |

กรณีมีประวัติ 9–14 วัน ทายระดับความร้อนถูก 94% / 93% / 92% ตามระยะล่วงหน้า

> **ข้อจำกัด:** ผลนี้ทดสอบกับสถานีวัดอากาศกลางแจ้ง ยังไม่ใช่ข้อมูลในคอกจริง ความแม่นยำในคอกจะวัดหลังติดตั้งที่ฟาร์มอย่างน้อย 2 สัปดาห์ด้วยสคริปต์ที่เตรียมไว้แล้ว เราลองโมเดล LSTM/GRU แล้วพบว่าแพ้วิธี hybrid จึงเลือกวิธีที่แม่นกว่า ไม่ได้เลือกวิธีที่ฟังดู "AI" กว่า

### 3.2 Computer vision นับท่าทางวัว (YOLO26m)
- โมเดล YOLO26m (ONNX, 480 px) แยก 4 ท่า: ยืน นอน กิน ดื่ม รันบน cloud
- ดัชนีความสบาย CCI = วัวนอน ÷ (นอน + ยืน) × 100 เพราะวัวที่ร้อนจะยืนมากขึ้นเพื่อระบายความร้อน
- ระบบเทียบ THI กับพฤติกรรมวัว เช่น THI สูงแต่วัวนอนเกือบหมด → สงสัยว่าเซ็นเซอร์คลาดเคลื่อน
- ผลบนชุดภาพทดสอบ 203 ภาพ: ตัดปัญหานับวัวซ้ำจาก 11 คู่เหลือ 0 คู่ จำนวนวัวนอนคลาดเคลื่อนเฉลี่ย 0.47 ตัวต่อภาพ แต่ยังพลาดวัวราว 21% เพราะโมเดลเทรนจากภาพต่างประเทศ
- ระบบจึงตั้งไว้ให้เก็บภาพตัวอย่างชั่วโมงละ 1 รูปลง bucket ส่วนตัว (จะยืนยันว่าภาพเข้าครบตอนติดตั้ง) ให้แอดมินนับเทียบแบบไม่เห็นคำตอบของโมเดล ถ้ายังนับเทียบไม่ถึง 30 ภาพ หน้าเว็บจะขึ้นว่า "ยังไม่ทราบความแม่นยำ"

### 3.3 สิ่งที่ยังไม่ได้ทำ (บอกตรงๆ)
- ยังไม่มี Gen AI ที่ทำงานในระบบตอนนี้
- ยังไม่ตรวจจับการหอบ (โมเดลไม่มีคลาสนี้)
- ยังไม่ติดตามวัวรายตัว
- หน้าสำหรับสัตวแพทย์ยังอยู่ระหว่างพัฒนา (ตอนนี้ข้อมูลดูได้ผ่านหน้าแอดมินและรายงาน)
- ยังไม่มีข้อมูลน้ำนม ระบบจึงไม่เคลมตัวเลขว่าน้ำนมจะลดกี่กิโลกรัมหรือกี่เปอร์เซ็นต์

## 4. ผู้ใช้และประโยชน์

| ผู้ใช้ | ใช้อะไร | ได้อะไร |
|---|---|---|
| เกษตรกร | สถานะคอก พยากรณ์ 3 วัน ช่วงที่คอกร้อนที่สุด | เปิดพัดลมก่อนร้อน เตรียมน้ำสำรอง ย้ายเวลาให้อาหารไปช่วงเย็น |
| สัตวแพทย์ (หน้าเฉพาะอยู่ระหว่างพัฒนา) | ชั่วโมงร้อน การพักฟื้นกลางคืน วันร้อนติดกัน (ข้อมูลมีในระบบแล้ว) | ข้อมูลประกอบเมื่อวัวกินอาหารลดหรือผสมไม่ติด และเลือกวันนัดผสมเทียมที่ไม่ร้อนจัด |
| สหกรณ์ | ตารางความเสี่ยงทุกฟาร์ม สมุดบันทึก 30 วัน เทียบในคอกกับภายนอก | จัดลำดับฟาร์มที่ควรได้พัดลม/ระบบพ่นน้ำก่อน มีหลักฐานประกอบการของบ |

## 5. สถาปัตยกรรมและเทคโนโลยี

เส้นทางข้อมูล:
1. กล่อง ESP32-S3 + SHT20 ในคอก ส่งค่าผ่าน HTTPS ทุก 15 วินาที → Node.js Express บน Render
2. กล้อง IP ใน LAN → ESP32 ดึงภาพนิ่งทุก 10 นาที → Node.js (YOLO26m)
3. Node.js ↔ Supabase (Postgres + Storage) และ Open-Meteo ECMWF
4. Node.js → Nuxt 3 บน Cloudflare Pages (หน้าเกษตรกร / หน้าแอดมิน)

- **อุปกรณ์:** ESP32-S3 (เฟิร์มแวร์ 1.4.1), XY-MD02 (SHT20, ±0.3°C / ±3% RH), กล้อง Dahua
- **Backend:** Node.js Express, ONNX Runtime (YOLO26m บน worker thread), node-cron สรุปประจำวัน 20:00 น.
- **ข้อมูล:** Supabase PostgreSQL + Private Storage, Open-Meteo (ECMWF IFS, Previous Runs API)
- **Frontend:** Nuxt 3, Cloudflare Pages
- **ความปลอดภัย:** ส่งข้อมูลผ่าน HTTPS ที่ตรวจใบรับรอง กล่องแนบ device key ทุกครั้ง (ตอนนี้เซิร์ฟเวอร์อยู่ในโหมดเตือน จะเปลี่ยนเป็นโหมดบังคับหลังยืนยันกล่องที่ติดตั้ง) ภาพกล้องเก็บใน bucket ส่วนตัว ข้อมูลจำลองติดป้ายแยก ไม่ปนกับผลวิเคราะห์จริง

## 6. สิ่งที่จะทำในค่าย Hackathon (แผน)

1. **Gen AI สรุปคำแนะนำภาษาง่าย:** ให้ LLM แปลงตัวเลขของระบบ (THI ชั่วโมงร้อน การพักฟื้นกลางคืน พยากรณ์) เป็นข้อความสั้นสำหรับผู้สูงอายุ โดย LLM ต้องใช้เฉพาะตัวเลขที่ระบบคำนวณแล้ว ไม่ให้แต่งตัวเลขเอง
2. **แจ้งเตือนผ่าน LINE รายฟาร์ม:** ผูกบัญชีด้วยรหัส 6 หลัก เตือนเมื่อเริ่มเหตุการณ์ความร้อน มีช่วงงดเตือนกลางคืน ไม่ส่งแบบ broadcast
3. **สรุปรายสัปดาห์:** เช่น "สัปดาห์นี้ร้อน 5 วัน คืนพักฟื้นได้ 2 คืน"

## 7. แผนต่อยอดหลังค่าย
- ติดตั้งฟาร์มจริง แล้ววัดความแม่นยำของพยากรณ์ในคอกและของกล้อง
- ร่วมกับสหกรณ์นำเข้าข้อมูลน้ำนมรายวัน (ต้องขอความยินยอมตาม PDPA) เพื่อหาว่า THI ระดับไหนในคอกนั้นทำให้น้ำนมลด
- เสนอเกณฑ์ THI เฉพาะคอกจากจุดหักของ % วัวนอน (ต้องมีข้อมูลอย่างน้อย 14 วัน และแอดมินต้องอนุมัติก่อนใช้)
- บันทึกวันปรับปรุงโรงเรือน แล้วเทียบ "ในคอกลบภายนอก" ก่อนและหลัง
