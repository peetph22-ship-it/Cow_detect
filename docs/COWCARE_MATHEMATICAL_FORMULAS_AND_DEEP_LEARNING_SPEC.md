## 📌 1. บทนำและภาพรวมระบบ (Executive Overview)
**CowCare AI** เป็นระบบเฝ้าระวังความเครียดจากความร้อนในโคนมลูกผสมไทย (Thai Crossbred Dairy Cattle) โดยผสานการทำงานระหว่าง:
1. **IoT Telemetry Sensing (`cowcare_sensor.ino` v1.4.1):** วัดอุณหภูมิและความชื้นสัมพัทธ์ในโรงเรือนด้วยโมดูล RS485 ตระกูล **XY-MD02 ชิป SHT20** ($\pm 0.3^\circ\text{C} / \pm 3\%\text{ RH}$) ผ่านบอร์ด ESP32-S3 พร้อมระบบสำรองข้อมูลลงแฟลช (`/q.bin`) เมื่อเน็ตหลุด และส่งรายงานสุขภาพกล่อง (Heartbeat) ทุก 5 นาที
2. **Unified Heat Stress Metrics (`heatStress.js` & `heatMetrics.js`):** คำนวณค่า $\text{THI}$ ตามสูตรมาตรฐาน **NRC (1971)** ชุดเดียวกันทั้งระบบ โดยแบ่งถังเวลาเฉลี่ยทุก **5 นาที** เพื่อคำนวณความครบถ้วนของข้อมูล ระดับความเครียดรายวัน ชั่วโมงพักกลางคืน และจำนวนวันเครียดติดต่อกัน
3. **Computer Vision Snapshot Pipeline (`visionService.js` & `visionPostprocess.js`):** บอร์ด ESP32-S3 ดึงภาพนิ่งจากกล้องวงจรปิด `Dahua DH-IPC-HFW2231TP-ZAS-S2` ทุก 10 นาที ส่งขึ้นเซิร์ฟเวอร์เพื่อรันโมเดล **YOLO26m ONNX (`best.onnx`)** บน Node.js Worker Thread นับวัวแยกตาม 4 ท่าทาง (**นอน / ยืน / กิน / ดื่ม**) พร้อมระบบตัดกรอบซ้อนแบบไม่ดูท่า (Class-Agnostic NMS)

## 🧮 2. สูตรการคำนวณทางคณิตศาสตร์และสัตวศาสตร์ (Mathematical & Physiological Formulations)

### 2.1 สูตรดัชนีอุณหภูมิและความชื้นมาตรฐาน (NRC, 1971)
ระบบใช้สมการ **NRC (National Research Council, 1971)** เพียงสูตรเดียวทั้งระบบ (`heatStress.calcThi` และ `heatStress.thiSql`) ซึ่งเป็นสมการเดียวกับที่งานวิจัยโคนมไทยใช้อ้างอิง (Sae-tiao et al., 2019):

$$\text{THI} = (1.8 \times T + 32) - (0.55 - 0.0055 \times \text{RH}) \times (1.8 \times T - 26)$$

* $T$ = อุณหภูมิภายในโรงเรือน ($^\circ\text{C}$)
* $\text{RH}$ = ความชื้นสัมพัทธ์ภายในโรงเรือน ($\%$)
* **ความคลาดเคลื่อนตามสเปกเซ็นเซอร์ (Sensor Uncertainty):** จากการตรวจรีจิสเตอร์ด้วย `sensor_probe_scan.ino` พบว่าหัววัดเป็นตระกูล XY-MD02 ชิป **SHT20** ซึ่งมีความแม่นยำตามสเปก $\Delta T = \pm 0.3^\circ\text{C}$ และ $\Delta \text{RH} = \pm 3\%$ เมื่อแทนค่าความคลาดเคลื่อนลงในสมการ $\text{THI}$ จะได้ความคลาดเคลื่อนของค่า $\text{THI}$ ประมาณ **$\pm 0.7$ หน่วย** (ยังไม่ได้เทียบกับเครื่องวัดอ้างอิงในฟาร์มจริง)

### 2.2 เกณฑ์จำแนกระดับความเครียดความร้อนสำหรับโคนมลูกผสมไทย
ความเป็นไทยของระบบอยู่ที่ **"ค่าเกณฑ์ (Thresholds)"** ที่อ้างอิงจากงานวิจัยโคนมลูกผสมไทยโดยตรง (ไม่ได้ดัดแปลงตัวสมการ NRC):

| ระดับความเสี่ยง (`riskLevel`) | ช่วงค่า THI (โคนมลูกผสมไทยทั่วไป) | ช่วงค่า THI (ฝูงสายเลือด HF สูง $\ge 87.5\%$) | ความหมายและงานวิจัยอ้างอิง | สัญลักษณ์สี |
| :--- | :---: | :---: | :--- | :---: |
| **ปกติ (`normal`)** | $\text{THI} < 74$ | $\text{THI} < 72$ | สภาวะปกติ โคพักผ่อนและระบายความร้อนได้ตามปกติ | 🟢 เขียว |
| **เฝ้าระวัง (`mild`)** | $74 \le \text{THI} < 76$ | $72 \le \text{THI} < 74$ | จุดที่น้ำนมเริ่มลดในแม่โคท้องที่ 3 ขึ้นไป สายเลือด HF $\ge 87.5\%$ (Boonkum et al., 2011) | 🟡 เหลือง |
| **เครียดจากความร้อน (`moderate`)** | $76 \le \text{THI} < 82$ | $74 \le \text{THI} < 80$ | จุดเริ่มเครียดระดับประชากรโคนมลูกผสมไทย น้ำนมและอัตราผสมติดเริ่มลดลง (Boonkum et al., 2024) | 🟠 ส้ม |
| **วิกฤต (`severe`)** | $\text{THI} \ge 82$ | $\text{THI} \ge 80$ | ผลผลิตน้ำนมลดลงเร็วขึ้นอย่างชัดเจน ต้องเร่งระบายความร้อนทันที (Boonkum et al., 2011) | 🔴 แดง |

> **ข้อควรทราบ:** เกณฑ์ในงานวิจัยกำหนดจาก $\text{THI}$ เฉลี่ยรายวันของสถานีอุตุนิยมวิทยา (นอกโรงเรือน) ระบบนี้วัดในโรงเรือนซึ่งมักร้อนกว่า จึงใช้ **$\text{THI}$ เฉลี่ยรายวัน** ในการจัดระดับความเสี่ยงของวัน และใช้ค่ารายชั่วโมงเพื่อเตือนช่วงเวลาที่ร้อน

### 2.3 วิธีคำนวณตัวชี้วัดรายวันและรายชั่วโมงแบบแบ่งถังเวลา 5 นาที (`heatMetrics.js`)
เพื่อให้ตัวเลขตรงกันทุกหน้า (หน้าเกษตรกร, หน้าแอดมิน, สรุปรายวัน 20:00 น., และสมุดสหกรณ์) ระบบจะนำค่าดิบจากเซ็นเซอร์มาเฉลี่ยลงใน **ถังเวลาละ 5 นาที ($\Delta t = 5\text{ นาที} = \frac{1}{12}\text{ ชั่วโมง}$)** โดย **ไม่เดาหรือเติมค่าในช่วงที่ไม่มีข้อมูล**:

1. **จำนวนชั่วโมงที่มีข้อมูลจริง (`data_hours`) และความครบถ้วนของข้อมูล (`coverage_pct`):**
   $$\text{Data Hours} = N_{\text{buckets}} \times \frac{5}{60}, \qquad \text{Coverage (\%)} = \min\left(100,\; \text{round}\left(\frac{\text{Data Hours}}{\text{Window Hours}} \times 100\right)\right)$$
   โดย $N_{\text{buckets}}$ คือจำนวนถังเวลา 5 นาทีที่มีข้อมูลเซ็นเซอร์ส่งเข้ามาจริง และ $\text{Window Hours}$ คือความยาวช่วงเวลาที่สรุป (เช่น 24 ชั่วโมง)

2. **ชั่วโมงเฝ้าระวัง / ชั่วโมงเครียด / ชั่วโมงวิกฤต (`watch_hours`, `stress_hours`, `severe_hours`):**
   $$\text{Watch Hours} = N_{\text{THI} \ge 74} \times \frac{5}{60}, \quad \text{Stress Hours} = N_{\text{THI} \ge 76} \times \frac{5}{60}, \quad \text{Severe Hours} = N_{\text{THI} \ge 82} \times \frac{5}{60}$$
   และสัดส่วนช่วงเวลาที่เครียดเทียบกับช่วงที่มีข้อมูลจริง:
   $$\text{Stress \% of Data} = \text{round}\left(\frac{N_{\text{THI} \ge 76}}{N_{\text{buckets}}} \times 100\right)$$

3. **ระดับความเครียดรายวัน (`daily_mean_level`):**
   คำนวณจากค่าเฉลี่ย $\text{THI}$ ของทุกถัง 5 นาทีในวันนั้น ($\overline{\text{THI}}_{\text{day}} = \frac{1}{N_{\text{buckets}}} \sum \text{THI}_i$) แล้วเทียบกับเกณฑ์ $74 / 76 / 82$

4. **ชั่วโมงกลางคืนที่วัวได้พักจากความร้อน (`night_relief_hours`):**
   พิจารณาเฉพาะถังเวลา 5 นาทีที่อยู่ในช่วง **22:00–06:00 น. (เวลาไทย)** และนับจำนวนชั่วโมงที่ $\text{THI} < 74$ (อิงตาม Igono et al., 1992 ที่ชี้ว่าความเย็นช่วงกลางคืนช่วยให้โคฟื้นตัวจากความร้อนสะสมช่วงกลางวัน):
   $$\text{Night Relief Hours} = N_{\text{night}(\text{THI} < 74)} \times \frac{5}{60}$$

5. **จำนวนวันเครียดติดต่อกัน (`stressStreak`):**
   นับจำนวนวันล่าสุดต่อเนื่องกันที่ $\overline{\text{THI}}_{\text{day}} \ge 76$ โดยนับเฉพาะวันที่มีข้อมูลอย่างน้อย **12 ชั่วโมง** (หรือสำหรับวันนี้ต้องมีข้อมูลอย่างน้อย **6 ชั่วโมง** หากวันใดมีข้อมูลไม่ถึงเกณฑ์จะหยุดนับทันทีเพื่อไม่ให้สรุปผิดพลาด)

### 2.4 การประเมินแนวโน้มความร้อนสะสม 72 ชั่วโมงและคำแนะนำตามบริบทไทย (`forecastService.js`)
1. **ค่าเฉลี่ยแนวโน้มความร้อนสะสม 72 ชั่วโมง (`baseline-72h-mean-v2`):**
   เมื่อมีข้อมูลรายชั่วโมงอย่างน้อย 24 ชั่วโมงในรอบ 72 ชั่วโมงล่าสุด ระบบคำนวณค่าเฉลี่ย $\text{THI}$ รายชั่วโมงย้อนหลัง 72 ชั่วโมง:
   $$\widehat{\text{THI}}_{\text{baseline}} = \frac{1}{M} \sum_{h=1}^{M} \overline{\text{THI}}_h \qquad (24 \le M \le 72)$$
   * **เหตุผลที่ใช้วิธีนี้แทน Bi-LSTM ในระยะปัจจุบัน:** จากการวัดผลด้วยสคริปต์ `eval_baselines.py` และ `eval_forecast.js` บนชุดข้อมูลสังเคราะห์ชุดเดียวกับที่ใช้เทรน พบว่าค่าเฉลี่ย 72 ชั่วโมงให้ค่าความคลาดเคลื่อน $\text{MAE} \approx 0.45\text{ THI}$ ซึ่งแม่นยำกว่าโมเดล Bi-LSTM เดิม ($\text{MAE} \approx 0.87\text{ THI}$) จึงปิด `ENABLE_LSTM=false` ไว้จนกว่าจะมีข้อมูลภาคสนามจริง
   * **ไม่แสดงตัวเลขกิโลกรัมน้ำนมลด:** ระบบยังไม่ประเมินปริมาณน้ำนมที่ลดลงเป็นกิโลกรัม เนื่องจากยังไม่มีข้อมูลบันทึกน้ำนมจริงจากฟาร์ม

2. **การหาช่วงเวลาร้อนที่สุดและเย็นที่สุดเฉพาะของแต่ละโรงเรือน (`findWindows`):**
   เนื่องจากโรงเรือนแต่ละแห่งร้อนสุดคนละเวลา (เช่น หลังคาสังกะสีมักสะสมความร้อนไปพีคช่วงบ่ายแก่หรือเย็น) ระบบจึงสแกนค่าเฉลี่ยรายชั่วโมงในรอบ 72 ชั่วโมงเพื่อหา:
   * **ช่วงร้อนที่สุด 4 ชั่วโมงติดต่อกัน (`peak_window`):** เพื่อแนะนำให้เน้นเปิดพัดลมระบายอากาศในช่วงเวลานั้น
   * **ช่วงเย็นที่สุด 3 ชั่วโมงติดต่อกันระหว่าง 04:00–20:00 น. (`cool_window`):** เพื่อแนะนำช่วงเวลาให้อาหารที่วัวกินได้ดีที่สุด

3. **กฎการใช้น้ำลดความร้อนตามความชื้นสัมพัทธ์ (`getCoolingAdvice`):**
   * เมื่อ $\text{RH} \ge 75\%$: **งดพ่นหมอกฝอย** (เพราะละอองหมอกละเอียดทำให้อากาศอิ่มตัวแต่ไม่ช่วยลดความร้อน) และแนะนำให้ **ฉีดน้ำเม็ดใหญ่ที่หลังและไหล่วัวให้เปียกช่วงสั้นๆ (เลี่ยงเต้านม) ร่วมกับเปิดพัดลมเป่าให้แห้ง**
   * เมื่อ $\text{RH} < 75\%$: สามารถเปิดพ่นหมอกหรือฉีดน้ำตัววัวร่วมกับเปิดพัดลมได้

## 🧠 3. สถาปัตยกรรมระบบ Computer Vision นับท่าวัว (`YOLO26m ONNX`)

```text
[ กล้อง Dahua DH-IPC-HFW2231TP-ZAS-S2 ]
    │  (บอร์ด ESP32-S3 ดึงภาพนิ่ง JPEG ผ่าน HTTP Digest Auth ทุก 10 นาที)
    ▼
[ HTTPS Upload ──► Node.js Backend (visionService.js) ]
    │
    ├──► [ Worker Thread: YOLO26m ONNX (best.onnx, IMGSZ = 480) ]
    │       ├── ตรวจจับกรอบวัว 4 ท่า: นอน (lying down), ยืน (standing), กิน (eating), ดื่ม (drinking)
    │       └── ตัดกรอบซ้อนโดยไม่ดูท่า (Class-Agnostic NMS: conf ≥ 0.25, IoU ≥ 0.70)
    │
    ├──► [ บันทึกผลนับท่าวัวลงตาราง behavior_logs ใน Supabase PostgreSQL ]
    └──► [ เก็บภาพตัวอย่างชั่วโมงละ 1 รูป + ไฟล์ JSON ลง Private Bucket (camera-samples) ]
```

### 3.1 รายละเอียดการทำงานและพารามิเตอร์ของโมเดล
* **ไฟล์โมเดลและการตรวจสอบความถูกต้อง (`modelStore.js`):** ไฟล์ `best.onnx` (สถาปัตยกรรม YOLO26m) ถูกเก็บใน Supabase Storage แบบ Private เมื่อเซิร์ฟเวอร์ดาวน์โหลดมาจะตรวจสอบค่าแฮช **SHA-256** ทุกครั้งก่อนโหลดเข้า `onnxruntime-node`
* **การประมวลผลภาพ (`visionWorker.js` & `visionPostprocess.js`):**
  1. ย่อขนาดภาพแบบรักษาสัดส่วน (Letterbox) ลงขนาด $480 \times 480$ พิกเซล (`IMGSZ = 480`)
  2. จำแนกท่าทางโคนมเป็น **4 คลาส**:
     * `lying down` (นอนพัก)
     * `standing` (ยืน)
     * `eating` (กินอาหาร)
     * `drinking` (ดื่มน้ำ)
  3. **การตัดกรอบซ้อนแบบไม่ดูท่า (Class-Agnostic NMS, `agnostic: true`):**
     หากมีกรอบทำนาย 2 กรอบซ้อนทับกันเกินเกณฑ์ $\text{IoU} \ge 0.70$ ระบบจะเก็บไว้เฉพาะกรอบที่มีความมั่นใจ (`conf`) สูงสุดเพียงกรอบเดียว **โดยไม่สนใจว่าเป็นคลาสเดียวกันหรือไม่** (บังคับกฎ **วัว 1 ตัว = 1 กรอบ**) เพื่อแก้ปัญหาวัวตัวเดียวถูกตีกรอบซ้อนกันหลายท่า
  4. **สัดส่วนวัวนอน (`lying_ratio`):**
     $$\text{Lying Ratio} = \frac{N_{\text{lying}}}{N_{\text{total detected}}}$$

### 3.2 ผลการทดสอบกับชุดภาพทดสอบ 203 ภาพ และข้อจำกัดปัจจุบัน
จากการทดสอบไปป์ไลน์ `YOLO26m ONNX` ร่วมกับ Class-Agnostic NMS บนชุดภาพทดสอบจำนวน **203 ภาพ**:
* **การแก้ปัญหานับวัวซ้ำ:** จำนวนคู่วัวที่ถูกตีกรอบซ้อนทับกันเกินเกณฑ์ลดลงจาก **11 คู่ เหลือ 0 คู่**
