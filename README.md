## 📌 1. เป้าหมายและแนวทางของโปรเจกต์

### 1.1 แนวทางที่เปลี่ยนไป (พ.ย. 2569)

| | เดิม | ปัจจุบัน |
| :--- | :--- | :--- |
| **ข้อมูลหลัก** | อุณหภูมิ + ความชื้น → THI และพยากรณ์ | **2 สายข้อมูลคู่กัน:** THI ในคอก + **ท่าทางของวัวเป้าหมาย 1 ตัว** |
| **บทบาทของกล้อง** | นับวัวทั้งฝูงแยกท่า ใช้ตรวจความแม่นยำของระบบ | **ติดตามวัว 1 ตัวที่คลิกเลือกบนภาพ** (ผูกเบอร์หู) แล้วสร้างไทม์ไลน์ นอน/ยืน/กิน/เดิน พร้อม THI ของแต่ละช่วง |
| **ผลลัพธ์ที่ใช้** | ชั่วโมงเครียดของคอก | ชั่วโมงเครียดของคอก **+ เวลานอน/ยืนของวัวตัวนั้นเทียบกับ THI ขณะนั้น** |

### 1.2 ทำไมต้องดูทั้งความร้อนและพฤติกรรม
1. **เกณฑ์ความเครียดความร้อนของโคนมลูกผสมไทย (Boonkum et al., 2011; 2024):** น้ำนมเริ่มลดที่ THI เฉลี่ยรายวัน **74** (แม่โคสายเลือดโฮลสไตน์ $\ge 87.5\%$ ท้องที่ 3 ขึ้นไป) จุดเริ่มเครียดระดับประชากร **76** และลดเร็วขึ้นเมื่อ THI $\ge 82$ ระบบเตือน **ความเสี่ยงน้ำนมลด** ตามระดับความร้อนสะสมจริง โดยไม่ระบุกิโลกรัมหรือเปอร์เซ็นต์ที่ไม่ได้วัด
2. **THI บอกว่าคอกร้อนแค่ไหน แต่ไม่บอกว่าวัวแต่ละตัวรับมืออย่างไร:** การเปลี่ยนเวลานอนพักและการยืนเป็นพฤติกรรมที่สังเกตได้จากกล้อง ระบบจึงบันทึกท่าทางของวัวเป้าหมายคู่กับ THI ทุกช่วงเวลา (ใช้เชิงพรรณนา ยังไม่สรุปว่าวัวเครียดจากข้อมูลวันเดียว)
3. **การพักฟื้นตอนกลางคืน (Igono et al., 1992):** นับชั่วโมงช่วง 22:00–06:00 น. ที่ THI ต่ำกว่า 74 (เกณฑ์เฝ้าระวังของระบบสำหรับโคลูกผสมไทย ไม่ใช่ค่าจาก Igono ซึ่งศึกษาโฮลสไตน์ในเขตทะเลทราย)
4. **ความชื้นสูง ($\text{RH} \ge 75\%$):** แนะนำฉีดน้ำตัววัวเป็นช่วงร่วมกับพัดลมแรง แทนการพ่นหมอก (Penn State Extension)
5. **ออกแบบสำหรับฟาร์มรายย่อย:** เกษตรกรไม่ต้องกรอกข้อมูลรายวัน ใช้กล่องเซ็นเซอร์และกล้องวงจรปิดที่มีอยู่ ไม่ต้องใช้ปลอกคออัจฉริยะ

### 1.3 ขั้นตอนปัจจุบัน
**เตรียมทดลองภาคสนาม:** ไปฟาร์ม **6 ธ.ค. 2569** (ติดตั้ง + วันทดสอบ) และ **7 ธ.ค. 2569** (วันเก็บข้อมูลจริง อัดวิดีโอเป็นคำตอบอ้างอิง) กล้องทุก 15 วินาที เซ็นเซอร์ทุก 15 วินาที เปเปอร์ส่งก่อนสิ้นปี 2569 โดย**เน้นตัวกล่องอุปกรณ์** (ความต่อเนื่อง ความครบของข้อมูล ความแม่นของเซ็นเซอร์ ปริมาณเน็ต การใช้ไฟ ต้นทุน) ส่วนพฤติกรรมวัวเป้าหมายเป็นตัวอย่างการใช้งาน

## 🧮 3. สูตรและเกณฑ์ความร้อน (`heatStress.js`, `heatMetrics.js`, `heatEvents.js`)

คำนวณที่ Backend ที่เดียว ทุกหน้าใช้ตัวเลขชุดเดียวกัน และใช้เฉพาะข้อมูลจริง (`is_simulation = false`)

### 3.1 สมการ THI (NRC, 1971)
$$\text{THI} = (1.8 \times T + 32) - (0.55 - 0.0055 \times \text{RH}) \times (1.8 \times T - 26)$$

* $T$, $\text{RH}$ จาก SHT40 (สเปกทั่วไป $\pm 0.2^\circ\text{C}$ / $\pm 1.8\%\text{ RH}$ ≈ THI $\pm 0.4$ ที่ 30 °C, 70 %RH; ความแม่นจริงในคอกวัดเทียบเครื่องอ้างอิงตอนทดสอบ) — สมการเดียวกับงานวิจัยโคนมไทย (Sae-tiao et al., 2019)

### 3.2 ระดับความเครียดความร้อน (Boonkum et al., 2011; 2024)

| ระดับ (`riskLevel`) | ค่าเริ่มต้น (`default`) | ฝูง HF สูง $\ge 87.5\%$ (`high_hf`) | ความหมาย |
| :--- | :---: | :---: | :--- |
| 🟢 ปกติ (`normal`) | THI < 74 | THI < 72 | กินและพักผ่อนได้ปกติ |
| 🟡 เฝ้าระวัง (`mild`) | 74–75.9 | 72–73.9 | น้ำนมเริ่มลดในแม่โคท้องที่ 3+ สายเลือด HF สูง |
| 🟠 เครียดจากความร้อน (`moderate`) | 76–81.9 | 74–79.9 | จุดเริ่มเครียดระดับประชากรโคลูกผสมไทย |
| 🔴 วิกฤต (`severe`) | ≥ 82 | ≥ 80 | น้ำนมลดเร็วขึ้นชัดเจน ต้องลดความร้อนทันที |

### 3.3 ตัวชี้วัด
* **ถัง 5 นาที:** เฉลี่ยค่าทุก 5 นาที ไม่เดาค่าในช่วงที่ไม่มีข้อมูล (กราฟเว้นว่าง ไม่ลากเส้นต่อ)
* **ความครบถ้วน (`coverage_pct`)**, **ชั่วโมงเครียด (`stress_hours`, THI ≥ moderate)**, **ชั่วโมงพักกลางคืน (`night_relief_hours`)**, **วันเครียดติดกัน (`stressStreak`)**, **ช่วงร้อนสุดของคอก (`peakWindow`)**
* **เหตุการณ์ (`heatEvents.js`):** THI ≥ moderate ต่อเนื่อง ≥ 30 นาที = เหตุการณ์ความร้อน, ไม่มีข้อมูล > 15 นาที = **ขาดการติดต่อ** (แสดงทั้งหน้าเกษตรกรและผู้ดูแล แม้กล่องเงียบนานกว่า 7 วัน)

## 📈 4. พยากรณ์ THI ล่วงหน้า 3 วัน (`forecastService.js`, `hybrid-ecmwf-bias-v1`)

พยากรณ์ THI เฉลี่ยรายวัน +1/+2/+3 วัน จาก **Open-Meteo ECMWF (`ecmwf_ifs025`)** หักลบค่าเพี้ยนมัธยฐานจากเซ็นเซอร์ฟาร์มย้อนหลัง **3–14 วัน** (วันที่ข้อมูล ≥ 20 ชม., จำกัด ±6 THI) ถ้าข้อมูลฟาร์มไม่ถึง 3 วันใช้ค่าเพี้ยนภาคเหนือ (`-1.41 / -1.37 / -1.32`) และถ้า API ขัดข้องถอยไปใช้ `best_match` หรือค่าเฉลี่ย 72 ชม. พร้อมแจ้งสาเหตุ

**ทดสอบย้อนหลังกับสถานีสนามบินเชียงใหม่ (WMO 48327) 354 วัน** (สคริปต์: [`backend/ml_lstm/forecast_eval/`](backend/ml_lstm/forecast_eval/README.md))

| วิธี | MAE +1 | MAE +2 | MAE +3 | หมายเหตุ |
| :--- | :---: | :---: | :---: | :--- |
| ค่าเฉลี่ย 72 ชม. | 1.10 | 1.38 | 1.56 | |
| ECMWF ดิบ | 1.34 | 1.32 | 1.35 | |
| **ECMWF + ปรับค่าเพี้ยน 14 วัน (ใช้จริง)** | **0.69** | **0.78** | **0.88** | ระดับความเสี่ยงตรง 94% / 93% / 92% |
| ECMWF + ปรับค่าเพี้ยน 3 วัน | 0.80 | 0.92 | 1.07 | เพิ่งติดตั้ง 3–8 วัน |
| ECMWF + ค่าเพี้ยนภาค (2024) | 0.77 | 0.83 | 0.90 | ข้อมูลฟาร์มไม่ถึง 3 วัน |
| LSTM (1,596 พารามิเตอร์, 3 seed) | 0.81 | 0.89 | 0.93 | แพ้ทุกระยะ จึงไม่ใช้ |
| GRU (1,212 พารามิเตอร์, 3 seed) | 0.88 | 0.91 | 0.91 | แพ้ทุกระยะ จึงไม่ใช้ |

> **ทำไมไม่ใช้ LSTM/GRU:** ข้อมูลเทรนมีแค่ 275 ตัวอย่าง (ลำดับ 14 วัน) และแพ้วิธีปรับค่าเพี้ยนทั้ง 3 ระยะ ส่วน Bi-LSTM รุ่นเดิม (`lstmOnnxService.js`) เทรนจากข้อมูลสังเคราะห์และปิดไว้ (`ENABLE_LSTM=false`) ชื่อ `dailyLstmScheduler.js` และคอลัมน์ `lstm_forecast` เป็นชื่อเดิม ข้างในเก็บผลพยากรณ์ hybrid

> **ข้อจำกัด:** วัดกับสถานีกลางแจ้ง ยังไม่ใช่โรงเรือน และระบบไม่ประเมินปริมาณน้ำนมที่ลดลง

## 🎥 5. กล้องและพฤติกรรมวัวเป้าหมาย

### 5.1 โมเดลตรวจจับ (`visionService.js`, `visionWorker.js`, `visionPostprocess.js`)
* **YOLO26m ONNX** (`yolo26m_480.onnx`, อินพุต 480×480) เก็บใน Supabase Private Bucket ตรวจ SHA-256 รันบน worker thread
* **4 ท่า:** `drinking`, `feeding`, `lying down`, `standing` — NMS ไม่ดูท่า (`conf 0.25`, `IoU 0.70`) วัว 1 ตัว = 1 กรอบ
* **ย่อภาพแบบยืดเต็มกรอบ (`RESIZE_MODE = 'stretch'`)** ให้ตรงกับภาพฝึก (Roboflow "Stretch") ใช้แบบเดียวกันทั้งเซิร์ฟเวอร์และหน้า simulator
* **เก็บกรอบวัวทุกตัวทุกภาพ** (`cctv_behavior_telemetry.detections`) เพื่อเลือกวัวย้อนหลัง แก้ตัวกลางทาง และใช้เป็นข้อมูลฝึกโมเดลต่อ แต่หน้า farm_detail **แสดงเฉพาะวัวเป้าหมาย**

### 5.2 ติดตามวัว 1 ตัว (`cowTargetTracker.js`, `cowTracking.js`, `cowBehaviorTimeline.js`)
* **เลือกวัว:** คลิกบนภาพล่าสุดหรือภาพย้อนหลัง พร้อมใส่ **เบอร์หู/ชื่อ** (`tb_cows.tag_id`, `name_cows`) ระบบคำนวณย้อนหลังจากภาพที่คลิกจนถึงปัจจุบัน แล้วติดตามต่อทุกภาพใหม่
* **วิธี `position-v2`:** กล้องติดตาย จึงจับคู่จากตำแหน่ง (ซ้อนทับ 70% + ระยะใกล้ 30%) และคาดตำแหน่งตอนวัวเดิน — ถ้ามี 2 กรอบใกล้พอๆ กัน (เสี่ยงสลับตัว) ถือว่า **"ไม่เห็นในภาพ" ไม่เดา**; หายเกิน 15 นาที = หลุดการติดตาม
* **ช่วงพฤติกรรม:** นอน / ยืน / กิน (ดื่มรวมกับยืน เพราะคลาสดื่มแม่นต่ำ) ตัดช่วงที่จุดกึ่งกลางระหว่างภาพ หายได้ 1 ภาพโดยไม่ตัดช่วง และภาพห่างเกิน 2.5 เท่าของรอบปกติ = ไม่มีข้อมูล
* **ทุกช่วงมี THI ขณะนั้น** + เวลานอน/ยืน/กิน, นอนนานสุด, การเดิน (จากการขยับของตำแหน่งเท้าเทียบกับขนาดตัว เกณฑ์จากการสั่นของกรอบตอนวัวนอนนิ่ง)
* **ข้อจำกัดที่รู้:** ติดตามด้วยตำแหน่งอย่างเดียว ถ้าวัวเป้าหมายนอนตรงที่วัวตัวอื่นเคยยืน อาจสลับตัว (กำลังทำแถบภาพยืนยัน + แก้ตัวกลางทาง)

### 5.3 หน้า Simulator (`/Admin/simulation`)
อัปโหลดวิดีโอ → ตรวจจับ 4 ท่าในเบราว์เซอร์ด้วยโมเดลและวิธีย่อภาพเดียวกับเซิร์ฟเวอร์ (onnxruntime-web, WebGPU/WASM) วิดีโอไม่ถูกส่งขึ้นเซิร์ฟเวอร์

### 5.4 ความแม่นยำ (ตรงไปตรงมา)

ชุดทดสอบเดิม (Roboflow 203 ภาพ) **มาจากกล้องเดียวกับชุดฝึกเกือบทั้งหมด และ 22% เป็นภาพเกือบซ้ำกับภาพฝึก** ตัวเลข mAP50 0.720 จึงเป็นความแม่นในคอกที่โมเดลเคยเห็น ไม่ใช่คอกใหม่

| ชุดทดสอบ (conf 0.25, ใช้ขั้นตอนเดียวกับเซิร์ฟเวอร์) | Precision | Recall | นับวัวคลาด (ตัว/ภาพ) |
| :--- | :---: | :---: | :---: |
| Roboflow ทั้งชุด (จำลองภาพกล้อง 16:9) | 0.82 | 0.78 | 0.92 |
| Roboflow เฉพาะภาพที่ไม่ซ้ำกับชุดฝึก | 0.80 | 0.72 | 1.27 |
| CBVD-5 มุมกล้องที่กันไว้ (154 ภาพ) | 0.82 | 0.70 | 1.64 |

* เมื่อเจอวัวแล้ว **ระบุท่าถูก:** นอน 99%, กิน 98%, ยืน 93% — ความผิดพลาดหลักคือ **หาวัวไม่ครบ** โดยเฉพาะวัวตัวเล็ก/ไกล (กว้าง < 6% ของภาพ เจอ ~30%)
* ชุดฝึกเดิมตีกรอบไม่ครบ (เทียบกับ CBVD-5 บนภาพเดียวกัน 969 ภาพ: ไม่มีกรอบ 2,481 ตัว, กรอบรวมหลายตัว 281 กรอบ) — กำลังฝึกรุ่น 2 จากชุดรวมที่ใช้กรอบ CBVD-5 ([`backend/training_archive/cbvd5/`](backend/training_archive/cbvd5/README.md))
* **ยังไม่ได้วัดในคอกไทย** — จะวัดด้วยภาพจากวันดูหน้างานและวันเก็บข้อมูล (ตีกรอบแบบไม่ดูคำตอบของโมเดล)

### 5.5 ฟีเจอร์ระดับฝูง (เดิม)
ดัชนี CCI (สัดส่วนวัวนอนในซอง), การตรวจความสอดคล้องเซ็นเซอร์–กล้อง (`multimodalValidationService.js`) และวิเคราะห์ % วัวนอนเทียบ THI (`lyingThiAnalysisService.js`) ยังอยู่ในระบบ แต่การศึกษาหลายวันพักไว้หลังส่งเปเปอร์

## 🚀 8. เริ่มพัฒนา

ดูคู่มือเต็มที่ [`docs/DEV_SETUP.md`](docs/DEV_SETUP.md)

```bash
# Backend (พอร์ต 5099) — ใช้ SECRET_KEY ของตัวเอง ห้ามใช้ token จากเครื่องนี้กับเว็บจริง
cd backend_node && cp .env.example .env && npm install && PORT=5099 npm start

# Frontend ชี้มาที่ Backend บนเครื่อง
cd frontend && npm install && NUXT_PUBLIC_NODE_API_BASE=http://localhost:5099/api npm run dev

# เทสต์ทั้งหมด
for f in backend_node/scripts/test_*.js; do node "$f" || echo "FAIL $f"; done

# รายงานซ้อมกล่อง/กล้อง (อ่านอย่างเดียว) ใส่ช่วงเวลาที่ซ้อมจริง
# เน็ตบางที่ต่อฐานข้อมูลช้า: ถ้าขึ้น connection timeout ให้ใช้ hotspot มือถือ
node backend_node/scripts/rehearsal_report.js --device ESP32-S3-01 --from "2026-12-06 09:00" --to "2026-12-06 15:00"

# ดึงภาพจากโหมดเก็บภาพทุกภาพ แล้วตรวจสำเนาก่อนลบออกจาก Storage (ต้องมี SUPABASE_URL + SUPABASE_SERVICE_ROLE_KEY ใน .env)
node backend_node/scripts/download_collected.js --farm <farm_id> --date 2026-12-06
node backend_node/scripts/free_collected.js --farm <farm_id> --date 2026-12-06 --backup <สำเนาที่ 2>          # ตรวจอย่างเดียว
node backend_node/scripts/free_collected.js --farm <farm_id> --date 2026-12-06 --backup <สำเนาที่ 2> --delete # ลบ (ต้องพิมพ์วันที่ยืนยัน)
```

| ตัวแปร (`backend_node/.env`) | ค่าเริ่มต้น | คำอธิบาย |
| :--- | :--- | :--- |
| `DATABASE_URL` | `postgresql://...` | Supabase PostgreSQL |
| `SECRET_KEY` | *(สุ่ม 32 ไบต์)* | ลงนาม JWT (เครื่องนักพัฒนาสร้างแยกของตัวเอง) |
| `DEVICE_AUTH_MODE` | `warn` | `enforce` = บังคับ `X-Device-Key` |
| `ENABLE_DAILY_CRON` | *(ว่าง)* | สรุปรายวัน 20:00 น. รันบน Render หรือเมื่อตั้งเป็น `1` เท่านั้น |
| `YOLO_MODEL_FILE` | `yolo26m_480.onnx` | ไฟล์โมเดลตรวจจับ |
| `CAMERA_INTERVAL_MIN` | `10` | รอบภาพในเฟิร์มแวร์ (นาที) ใช้เมื่อกล่องไม่ได้ตั้งรอบจากหน้าอุปกรณ์ (ขาดการติดต่อ = ไม่มีภาพใหม่เกิน 4 รอบ อย่างน้อย 5 นาที) |
| `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | *(ว่าง)* | Storage ภาพ (server) และสคริปต์ดึง/ลบภาพบนโน้ตบุ๊ก · คีย์สิทธิ์สูงสุด ห้าม commit |
| `DB_CONNECT_TIMEOUT_MS` | `10000` | เวลารอต่อฐานข้อมูล (สคริปต์รายงานซ้อมตั้ง 30000 + ลองใหม่ 3 ครั้งเอง) |
